# 3D 特效第三阶段使用说明

前两个阶段已由用户反馈测试通过。第三阶段增加软粒子和普通颜色目标上的 Bloom 泛光。按项目要求，本阶段未运行编译或浏览器测试，以下行为仍需验收。

## 软粒子

软粒子在烟雾、火焰等透明物体与不透明场景相交时，按深度差逐渐降低透明度，减轻明显的硬交界。

```haxe
// 可用于粒子、广告牌、拖尾及其他透明网格的材质。
material.softParticleDistance = 0.5;

// 零关闭，恢复普通深度遮挡。
material.softParticleDistance = 0;
```

`Material3D.softParticleDistance` 默认零，仅 `AlphaMode3D.BLEND` 阶段生效，必须为非负有限值。数值表示淡出范围，以当前透视相机视轴方向的距离差计算；普通未缩放相机下使用世界单位。值较大时交界更柔和，但可见区域也会被更多衰减。

实现过程：

1. 检查场景中是否存在请求软粒子的透明材质。
2. 将具有深度写入的不透明及 MASK 裁剪网格预绘制到独立深度纹理目标。此路径复用材质 Shader，因此会保留透明裁剪及自定义 UV 的深度轮廓。
3. 主场景正常绘制。软粒子 Shader 使用屏幕位置读取预绘制深度，再根据相机近远裁剪面线性化深度。
4. 按场景与粒子的深度差衰减 alpha；加法混合的 RGB 也随 alpha 衰减。

预绘制目标和主目标使用相同尺寸、视口及相机。采样深度纹理不会同时作为主场景的绘制附件，避免纹理反馈。空背景深度为一时不衰减粒子。

注意：

- 透明物体之间不互相提供软粒子深度，也不支持通过这项能力完成透明网格排序。
- 关闭深度写入的网格不提供软粒子深度。MASK 网格只有通过透明阈值的片元写入深度。
- 该效果不修改粒子模拟、碰撞或几何，只改变可见透明度。
- 深度采用当前透视相机的近远裁剪面重建；不提供自定义投影矩阵的深度重建接口。
- 深度附件为 16 位，过大的近远平面比例会降低远处交界的精度；应使用适合场景尺度的相机裁剪范围。
- 这是额外的不透明场景预绘制，未做 GPU 深度复制优化，开启后会增加绘制、上传与离屏显存开销。

如果设备不支持深度纹理、片元高精度不足、预留纹理槽位不足或深度目标创建失败，会回退到普通透明绘制。原因见 `scene.stats.softParticleStatus`。分配失败会在该功能保持启用期间停止重复尝试；关闭全部软粒子后再次启用，或重建上下文后可重试。

## Bloom 泛光

```haxe
scene.bloom.enabled = true;
scene.bloom.threshold = 0.45;
scene.bloom.intensity = 1.4;
scene.bloom.radius = 2.5;
scene.bloom.renderScale = 0.5;
```

每个 `Scene3D` 自带 `BloomSettings3D`，默认关闭。参数变更通过场景设置键参与按需重绘。

| 参数 | 默认值 | 范围与作用 |
| --- | --- | --- |
| `enabled` | `false` | 开启泛光 |
| `threshold` | `0.65` | 零至一，以显示空间 RGB 最大分量提取亮部 |
| `intensity` | `0.8` | 零至八，最终叠加的光晕强度 |
| `radius` | `2` | 零至十六，模糊偏移倍率，单位为降采样目标像素 |
| `renderScale` | `0.5` | 0.125 至一，相对于实际三维离屏目标尺寸 |

泛光使用两个颜色纹理目标，执行三次全屏绘制：亮部提取、水平模糊、垂直模糊。最终在三维视口合成到二维时叠加结果，不额外覆盖场景 alpha。透明背景上的加法光效和光晕均保留 RGB 发光分量，并跟随视口透明度与颜色倍率。

本阶段使用普通 RGBA8 颜色目标，不依赖浮点纹理或 HDR。阈值通常需要小于一；超过颜色目标范围的亮度在提取之前已经被限制，因此无法用强度大于一的材质值获得 HDR 泛光层次。当前为整个三维视口的亮部泛光，没有独立的特效选择遮罩；较亮的普通物体、天空或背景也会参与。

关闭泛光时沿用原来的单贴图合成 Shader，不执行提取和模糊，也不绑定泛光纹理。开启后才按需创建泛光程序及目标；关闭后释放泛光目标，合成程序可留作复用。目标分辨率变化时重新分配。静态视口复用离屏内容时也复用泛光结果，不重复执行三个通道。

设备至少需要两个纹理槽位用于泛光最终合成；创建或编译失败时回退到正常场景合成，原因见 `scene.stats.bloomStatus`。关闭后重新开启或重建上下文可重试。

## 纹理槽位与后端

主渲染通道的可用纹理槽位按以下顺序分配：

- 阴影开启时，预留设备末尾的一个槽位。
- 软粒子启用时，再预留一个场景深度槽位。
- 每个材质先扣除辅助贴图槽位，剩余槽位用于基础多纹理批次。

如果全场景预留软粒子深度后，任一参与绘制材质无法容纳至少一张主贴图及其辅助贴图，本帧全局回退软粒子，避免破坏原有材质。Bloom 在后处理和合成时单独使用纹理槽位，不继续占用主通道的槽位。

核心库修改：

- `Material3D`：增加软粒子距离，保留新内置 uniform 名称。
- `Scene3D` 与 `BloomSettings3D`：增加泛光设置及重绘检测。
- `Scene3DStats`：增加额外通道状态、绘制数量与显存估算。

`hxmaker-openfl` 同步增加 `BloomPass3D`，扩展 `Scene3DRenderTarget` 的可采样深度和纯颜色目标，更新材质批次、Shader、uniform 反射及渲染调度。目标、程序及缓存随视口销毁或上下文重建释放／失效；状态保护继续沿用既有后端协议。

## 统计与性能

| 字段 | 含义 |
| --- | --- |
| `softParticleStatus` | 软粒子关闭、启用或回退原因 |
| `softDepthDrawCalls` | 最近一次场景重绘中的深度预绘制批次数 |
| `softDepthTriangles` | 深度预绘制三角形数量 |
| `softDepthUploadedBytes` | 深度预绘制上传字节数 |
| `softDepthTargetBytes` | 独立深度目标估算显存，包含兼容颜色附件 |
| `bloomStatus` | 泛光关闭、启用或回退原因 |
| `bloomDrawCalls` | 最近一次场景重绘的泛光通道数量，正常开启为三 |
| `bloomTargetBytes` | 两个降采样颜色目标估算显存 |
| `postProcessCpuMs` | 泛光 CPU 提交耗时，需开启场景 profiling；不是 GPU 时间 |

原有 `drawCalls`、`triangles`、`uploadedBytes` 继续表示主场景通道，不混入深度预绘制与泛光。估算总目标显存时，将原有 `targetBytes`、`shadowMapBytes` 与新增两个目标字节数字段相加。全局 OpenFL 绘制统计也包含实际新增提交。

`mainCpuMs` 现在包含可选软粒子深度预绘制和主场景绘制；泛光单独计入 `postProcessCpuMs`，最终二维合成仍计入 `compositeCpuMs`。缓存合成帧不产生新的深度／泛光绘制，但计数保留最近一次实际重绘的结果，需结合 `redrawThisFrame` 判断。

例如实际三维目标为宽 W、高 H：基础颜色与深度目标约占 `6WH` 字节，软粒子独立目标额外约占 `6WH` 字节，泛光两个目标额外约占 `8 × floor(W × renderScale) × floor(H × renderScale)` 字节，最小宽高为一。设备像素比例会放大实际 W、H。建议只对需要的烟雾材质开启软粒子，并根据设备降低泛光分辨率。

## 示例与待执行验收

沿用 `samples/effects-3d`，入口保持 `HxmakerApplication`。示例默认开启两项效果，新增贴地烟雾和不透明方块，保留前两个阶段的粒子、刀光、拖尾、流光溶解及镜头控制。

- 点击“软粒子”：对比烟雾与地面、方块交界的淡出。
- 点击“泛光”：对比火球、刀光和光圈周围的光晕。
- 点击标题暂停特效后仍可拖动旋转和滚轮缩放。
- 轻点视口切换背景透明度，观察光晕是否正确叠加。
- 底部显示软粒子及泛光实际状态，以及深度／泛光绘制数量。

本阶段尚未运行编译或测试。建议人工验证：

1. 编译并运行 HTML5 示例，检查新 Haxe 类、Shader 和 framebuffer 是否正常。
2. 独立开关软粒子与泛光，观察效果及新增绘制统计，关闭两项时回归原有画面。
3. 旋转镜头、暂停、改变视口尺寸／渲染比例、切换透明背景，检查深度位置、光晕朝向及边缘没有翻转或错位。
4. 在 MASK 裁剪物体后方放置烟雾，确认裁剪区域和实际深度一致；检查透明物体不会错误贡献深度。
5. 回归带阴影和多辅助贴图的材质，检查纹理槽位、采样器及二维界面状态没有相互污染。
6. 检查按需重绘、反复开关、视口销毁／重建及上下文恢复，观察额外目标是否正确释放和重建。
7. 在支持与不支持深度纹理／片元高精度的设备上检查状态与回退；验证泛光分配失败时场景仍可正常合成。

场景颜色采样、局部热浪扭曲、HDR、选择性泛光、GPU 粒子和实例化属于后续增强。
