# 静态阴影几何缓存

后续已接入 `shadowMobility` 静态／动态分离，参见[静态与动态阴影缓存使用说明](静态与动态阴影缓存使用说明.md)。以下保留第一阶段静态缓存实现记录。

阴影通道为各级联保留原有合批后的顶点、索引和 GPU 缓冲。光照矩阵或相机取景变化时，只要投射物集合与几何内容保持一致，就直接绘制已有缓冲，不再遍历三角形、重建索引映射或上传顶点。

无需业务开启额外开关，仍遵循原有的阴影自动更新、手动冻结和画质设置。

## 失效与缓冲复用

- 投射物集合、可见性、几何对象或版本、世界变换、裁剪模式和 MASK 布局变化时，重建对应级联的几何。
- 父级变换、负缩放、蒙皮或业务修改顶点后调用 `Geometry3D.invalidate()` 都会进入正常失效路径。
- MASK 的 UV、逐顶点透明度和图集区域参与缓存检测；透明度、裁剪阈值等采样参数更新阴影贴图，但不单独触发几何上传。
- 几何重建复用已有 GPU 缓冲及 CPU TypedArray。容量不足时按二次幂增长，容量足够时通过 `bufferSubData` 更新实际使用部分。
- 保留原有 65535 顶点和 196605 索引的批次上限，不因缓存改为逐模型绘制。
- 关闭阴影、无投射物或接收物、场景销毁时释放缓冲；设备丢失时丢弃旧句柄，恢复后重新创建。

缓存按级联维护，投射物集合变化或动态物体移动会使对应级联重建。本次保留原有合批边界；没有引入会增加 DrawCall 的逐模型缓存。缓冲保留其最高使用容量以便复用，CPU 端 TypedArray 另占近似相同的容量，关闭阴影或销毁场景时释放。

## 统计

`Scene3DStats` 新增：

| 字段 | 含义 |
|---|---|
| `shadowGeometryCacheHits` | 本次阴影重绘中复用几何的级联数 |
| `shadowGeometryRebuilds` | 本次阴影重绘中重建几何的级联数 |
| `shadowGeometryBytes` | 当前阴影几何 GPU 缓冲预留字节数，不含深度贴图和 CPU 副本 |

`shadowCacheHit` 仍表示阴影贴图复用，与几何缓存不同。`shadowUploadedBytes` 按实际传输的数据计数，包括扩容时上传的预留容量；命中几何缓存时为 0。普通三维画面缓存合成时，绘制统计沿用最近一次重绘。

## 验证

独立验证入口：`test/shadow-cache`。浏览器检查脚本：`test/tools/run-shadow-cache-browser.cjs`。检查将缓存绘制与强制重建后的场景像素逐字节对照，覆盖相机和光方向变化、缓冲身份复用、模型及父级变换、负缩放、几何替换、MASK、容量上限、两级阴影、关闭重开、设备恢复和销毁。

在验证入口目录执行 `lime build html5`，在仓库根目录启动静态 HTTP 服务后运行检查脚本。定义 `hxmaker_3d_no_vao` 并设置脚本环境变量 `HXMAKER_WEBGL1=1 HXMAKER_NO_VAO=1` 可检查 WebGL 1 无 VAO 路径。脚本支持 `PLAYWRIGHT_MODULE`、`CHROME_PATH` 和 `HXMAKER_TEST_BASE`。

WebGL 2 默认 VAO 路径与 WebGL 1 无 VAO 路径各 14 项专项检查通过，包含场景销毁后原 GPU 句柄失效的检查。验证记录保存在 `test/shadow-cache/Validation/`。

观测站原有 14 项探索回归通过，屏幕按钮检查按实际逻辑缩放比例换算坐标，兼容当前 1920×1080 启动配置。软件 WebGL 的检查用于验证像素和资源行为，不能直接推断硬件 FPS 提升。
