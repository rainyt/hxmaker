# 渲染缓冲增量构建：第一期实施与验证记录

> 1.2.0 集成入口与最新验证见《1.2.0渲染优化同步记录.md》。本文中的开发分支及未提交状态描述对应历史阶段。

日期：2026-11-11。关联提议：https://github.com/rainyt/hxmaker-openfl/issues/11 。

## 实施结果

已在两个仓库的 `codex/incremental-render-buffer-20261111` 本地分支完成第一期实现与验证。改动尚未提交或推送。

生产代码位于 hxmaker-openfl：

- `src/hx/render/ImageBufferData.hx`：维护批次独立的稳定前缀记录，区分正在构建和已完成构建，截断失效尾部；保留独立全量写入路径。
- `src/hx/render/ImageBufferEntry.hx`：保存实际矩阵、尺寸、UV输入和颜色分量，按属性跳过写入，不依赖共享脏标记和世界矩阵版本。
- `src/hx/core/Render.hx`：默认启用普通图片和字形的增量构建；提供 `incrementalBufferEnabled` 全量回退开关。遮罩、shader、滤镜、自定义对象、离屏源和 cacheAsBitmap 作用域仍全量构建。
- `src/hx/render/BufferBuildStats.hx`：仅定义 `hxmaker_buffer_stats` 时写入计数；普通发行构建无逐对象计数成本。

纹理登记和 sampler 绑定每轮照常重建，因此无需在每条记录额外持有底层纹理引用；只有本轮实际纹理 ID 一致时才跳过 ID 属性写入。纯图片前缀每项固定四个顶点，槽位索引唯一确定所有缓冲偏移，Graphics 一旦进入就使本批缓存失效。

连续含 Graphics 的批次跳过记录采集，避免每帧创建随后丢弃的记录。离开不支持的作用域后，经过全量预热再恢复缓存。

## 生命周期审计

只读检查当前 OpenFL 9.2.8 的 Graphics、DrawCommandBuffer 与 ShaderBuffer：

- drawTriangles 的命令保存 Vector 引用，未复制几何缓冲。
- beginShaderFill 调用 ShaderBuffer.update，把 shader 参数写入自己的参数存储。
- 保留原有 Render.clear、缓冲批次所有权和提交时序，没有给多个批次共享可写 Vector。
- 没有修改 OpenFL 或 Lime。

## 发现并解决的退化

最初的增量版本在完整颜色、矩阵、UV与透明度同时逐帧变化时，中位构建耗时约退化 11%。

现在当已具备缓存的批次中，至少半数图片同时重写几何、UV和完整颜色时，暂停该批增量构建 60 次。退让期间只对首项做轻量稳定性探测；若仍变化则延后重新采集，避免周期性全批探测抬高 P95。稳定后重新采集一轮，再启用复用。

这是性能启发式，判断只影响是否复用，完全不影响正确性。首项不代表全部图片，因此不同场景的探测效率仍可能不同；强制全量开关始终可用。

## 正确性与回归

最终全量对照检查 **467552 次**，包括每批的模式、纹理顺序、缓冲长度和各属性分量；使用保留的全量写入函数作为独立参照，不共用缓存的计算代码。

覆盖稳定帧、父级变换与透明度、原地改矩阵/颜色/rect、纹理替换与尺寸变化、显隐与换序、重挂节点、纹理上限、颜色布局开关、同一对象重复提交及跨渲染器、1000→10→1000 项、未结束构建重置、Graphics 混排、真实 Label 排字与对象池、文字图集替换、特殊作用域回退、滤镜异常恢复、公开入口覆写次数，以及 1200 个确定性随机变更帧。还验证了退让与恢复过程。

Chrome 的真实 OpenFL WebGL 提交连续 **96 帧逐像素一致**，验证到实际绘制的非空内容和 817 次槽位复用。包括文字、嵌套遮罩、滤镜输出、shader 切换和 cacheAsBitmap。运行使用 SwiftShader 软件 WebGL 后端；不将它当作移动设备 GPU 性能结果。

既有输入框溢出回归通过 94 项断言，右键菜单回归通过 97 项断言，`vscode-openfl.hxml` 开发构建通过。

## 性能基准

环境：macOS arm64，Haxe 4.3.7，Node 22.14.0。每场景 4000 张图片，预热 100 帧后采样 350 帧；每帧交替两种构建模式的计时顺序。独立运行三轮，关闭诊断计数。表中取三轮各统计量的中位数，原始结果保留在末尾。

只测 CPU 缓冲构建，不含场景更新、全量快照分配、OpenFL 实际提交或 GPU 上传；对照是当前保留的独立全量路径，不能把这些比例理解为整帧或整个引擎加速。

| 场景 | 全量中位数 ms | 增量中位数 ms | 全量 P95 ms | 增量 P95 ms |
| --- | ---: | ---: | ---: | ---: |
| 静止多数 | 0.2385 | 0.1333 | 0.3369 | 0.2053 |
| 全部移动 | 0.2336 | 0.1644 | 0.3327 | 0.2405 |
| 持续换序 | 0.2282 | 0.2347 | 0.3009 | 0.2871 |
| 矩阵、UV与透明度同时变化 | 0.2275 | 0.1897 | 0.2948 | 0.2832 |
| 完整颜色静止 | 0.3769 | 0.1588 | 0.4868 | 0.2286 |
| 完整颜色全动态 | 0.5750 | 0.5739 | 0.7211 | 0.7192 |

静止多数场景三轮的配对中位耗时减少约 43%–44%，完整颜色静止场景约减少 55%–60%。持续换序场景约增加 1%–3%；完整颜色全动态在退让后中位耗时与全量接近，三轮 P95 配对变化约为 -1.3% 至 +3.2%。

## 复现命令

本机的 Haxe manager 包装器缺少标准库路径，实际使用 `/usr/local/bin/haxe`（4.3.7）。其他环境可用已正确配置的 `haxe`。

```bash
/usr/local/bin/haxe test/incremental-buffer.hxml -D hxmaker_buffer_stats
node --require ./test/context-menu-preload.js bin/incremental-buffer-check.js

/usr/local/bin/haxe test/incremental-buffer.hxml -D buffer_benchmark
node --require ./test/context-menu-preload.js bin/incremental-buffer-check.js

/usr/local/bin/haxe test/incremental-buffer-browser.hxml
node test/run-incremental-buffer-browser.cjs
```

浏览器脚本需要 Playwright，可在项目外安装，通过 `HXMAKER_PLAYWRIGHT_MODULE` 指向模块目录；也可用 `HXMAKER_CHROME` 指定 Chrome 可执行文件。本次 Playwright 安装在临时目录，没有改动项目依赖。

## 验证边界

本轮没有单独运行 Spine 动画、微信等小游戏真机或原生平台；这些输出中的 Graphics 仍走原全量构建。特殊 shader、滤镜也继续全量回退。没有修改绘制顺序或主动增加批次。

当前记录容量随活跃槽位有界，缩短批次和退出作用域都会丢弃过期记录或对象引用；尚未提供各目标运行时的精确内存占用测量。
