## 1. 目标与边界

业务项目不改代码，直接降低重绘帧的 CPU 缓冲构建成本。保留原来的对象遍历、绘制顺序、切批、纹理登记、遮罩、滤镜和提交行为。

第一期优化普通 Image 和普通 Label 内部字形 Image 的稳定缓冲片段，按属性分别复用世界顶点、UV、颜色与透明度、混合参数、索引和纹理 ID。

不承诺减少 DrawCall 或 GPU 上传；OpenFL 的 drawTriangles 和 ShaderParameter 提交可能仍复制完整数据。必须把“缓冲构建耗时”与“整个渲染帧耗时”分别测量。不得修改 OpenFL 或 Lime。

## 2. 已确认的源码事实

主要位置：

- hxmaker-openfl `src/hx/render/ImageBufferData.hx`：draw 每次重写图片的全部属性；原先基于脏标记的跳过逻辑已经注释。
- 同文件 drawGraphic：Graphics 与 Image 共用缓冲，但顶点数、索引数不固定。
- 同文件 reset/endFill：构建游标归零；提交时会缩短各属性数组与 Vector 的实际长度。
- hxmaker-openfl `src/hx/core/Render.hx`：每轮从第零个批次重新构建，纹理映射重建；endFill 截断多余批次。
- hxmaker-openfl `src/hx/render/TextFieldRender.hx`：字形有对象池，世界矩阵直接写入，不能假设其世界矩阵版本一定更新。
- hxmaker `src/hx/display/BitmapData.hx`：data、rect、frameRect 是公开可变字段。
- hxmaker `src/hx/geom/ColorTransform.hx`、`Matrix.hx`：分量可原地修改。

这些事实解释了为何仅恢复 `if (__transformDirty)` 一类判断不可靠，但不能据此断言已经覆盖历史问题的全部根因。

## 3. 原方案容易失效的条件

| 条件 | 仅看对象脏标记的风险 | 新方案约束 |
| --- | --- | --- |
| visible、插入、删除、换序、重挂父节点 | 同一槽位已经换成另一个对象 | 比对槽位对象与全部缓冲起点 |
| 纹理数量、平滑、颜色模式、shader、混合模式变化 | 前后批次边界不同 | 先执行原切批逻辑，再判断缓存 |
| 同一对象跨渲染器或同轮多次绘制 | 第一次绘制已经清除共享脏标记 | 每个缓冲持有独立值快照 |
| transform、ColorTransform、rect 原地修改 | setter 未触发，版本或引用不变 | 比对参与输出的实际数值 |
| 字形对象池复用、文本图集替换 | 对象身份相同但输出数据已变化 | 身份和实际矩阵、纹理、UV、尺寸一起校验 |
| 缓冲先长、再短、再长 | 缩短 Vector 后旧尾部不再有效 | 提交时丢弃超出有效前缀的记录 |
| Graphics 和 Image 混合 | 不规则顶点覆盖旧图片记录的范围 | 首期用保守屏障回退 |
| 普通帧和离屏绘制交替、异常中断 | 未完成或其他构建上下文的记录被复用 | 构建作用域隔离，异常后不复用未提交记录 |

## 4. 核心正确性规则

**只有可以证明当前片段中的字节仍等于本次全量构建结果，才允许跳过写入。**

不使用“对象没变脏，所以缓冲正确”作为证明。对象脏标记只能作为将来额外优化的提示，第一期正确性依靠每个缓冲自己的输入值快照。

缓存命中需要同时满足：

1. 缓冲属于同一个 Render 实例，记录来自该缓冲上一次成功完成的构建。
2. 本轮尚未出现结构失配或不支持的命令。
3. 当前记录的命令种类、对象身份、顶点起点、索引起点和属性起点完全一致。
4. 对应属性片段仍在上轮有效长度内，没有被其他命令覆盖或被 resize 丢弃。
5. 当前属性的所有实际输入与快照相同。
6. 本轮纹理和 shader 模式已经按照原逻辑确定。

相同身份不代表相同数据；相同版本也不能代替直接写入路径的数值校验。

## 5. 数据归属与记录结构

缓存元数据放在 ImageBufferData 内，不放在 Image 的全局共享状态，也不使用静态跨渲染器槽位表。

建议记录为有显式类型的内部结构，分量保存为数值副本，不能只保存可变 Matrix、Rectangle 或 ColorTransform 的引用。

每个图片记录包含：

- 对象引用、命令类型，以及各缓冲起点和长度。
- 世界矩阵 a/b/c/d/tx/ty、实际绘制宽高。
- 实际底层纹理身份与尺寸、rect 是否存在及 x/y/width/height；缓存归一化 UV。
- 世界 alpha、有效 ADD 参数、ColorTransform 是否存在与八个实际分量。
- 本批有效颜色属性布局、本轮纹理 ID。
- 上次写入有效的属性位与构建代次。

记录按槽位复用，不在每个重绘帧分配新记录或临时 key 数组。记录尾部失效时清除对象、纹理引用，避免缓存长期持有退场资源。缓冲释放时同时释放记录。

首期采用明确字段比较；不引入可能碰撞的数值 hash。NaN 等不可稳定比较的输入自然回退写入。

## 6. 属性失效矩阵

| 属性片段 | 必须校验的实际输入 | 变化后写入 |
| --- | --- | --- |
| 世界顶点 | 世界矩阵六分量、实际绘制宽高 | 8 个坐标分量 |
| UV | rect 状态及四分量、实际纹理尺寸 | 8 个 UV 分量 |
| alpha | 实际 worldAlpha | 4 个透明度分量 |
| ADD 参数 | 实际 addBlendMode | 4 个混合标记 |
| 颜色 | 本批颜色布局、颜色变换存在性及八分量 | hasColorTransform、multiplier、offset |
| 纹理 ID | 本轮纹理登记产生的实际 ID | 4 个 ID |
| 索引 | 图片拓扑、索引起点和顶点基址 | 6 个索引 |

纹理身份改变必须重新走原纹理登记；即使 UV 数值相同，也不能复用旧 sampler 绑定。帧图偏移若改变世界矩阵，由最终矩阵校验覆盖。平滑、shader、blendMode 主要影响切批与本批布局，不能只当成图片属性处理。

颜色布局从快速模式切到完整模式时，旧颜色数据即使曾经存在，也必须重新证明有效。数组已经被缩到零的属性，重新启用时全部写入。

## 7. 构建顺序与回退

每次 draw(Image) 的处理顺序：

1. 完整执行现有切批判定，不改变失败返回和重试流程。
2. 完整执行本轮纹理登记，取得本轮纹理 ID 和有效颜色布局。
3. 读取一次本次构建使用的实际输入，判断结构是否与旧记录匹配。
4. 结构匹配时按属性分别比较：只写变化片段，其余保留原缓冲内容。
5. 结构不匹配时，从当前记录开始关闭本批本轮的缓存复用，后续按原流程全量写入。
6. 不论是否命中，全部游标必须与全量路径推进相同，原有脏标记清理仍按原流程执行。
7. 成功提交后保留本轮有效记录，丢弃尾部，并同步全部属性的真实有效长度。

属性变化不等于结构变化。例如只改 alpha，仍可复用顶点、UV、索引。对象身份、命令种类或偏移不匹配才触发结构回退。

第一期只复用稳定前缀，不做失配后向后搜索或中间片段重新匹配。这样可见性频繁变化时收益可能有限，但回退路径明确，下一轮结构稳定后可以重新命中。

缓存保留不等于延长对外提交长度：提交的顶点、索引、UV 和 shader 属性长度继续精确等于本轮实际数量，不能为保留容量而提交旧尾部。

## 8. Graphics、文字和特殊渲染

### Graphics

以下为第一期限制，第二轮已移除整批禁用，当前混排规则与验证见《渲染缓冲混排增量构建验证记录.md》。

首期 drawGraphic 全量写入，保持现有切批与绘制行为：

- 上次构建含 Graphics 的批次，本轮整批不复用。
- 本轮首次遇到 Graphics，从该命令开始关闭本批余下命令的复用，并使相关记录失效。
- 当前已命中的图片前缀只读未覆盖的有效区间；Graphics 从当前游标追加，不能覆盖已提交的前缀区间。
- 不额外拆批以绕开 Graphics，避免增加 DrawCall。

九宫格、repeat、路径抗锯齿、Spine 等经 Graphics 输出的路径首期均全量构建。

### 普通 Label 字形

继续使用现有 ImageRender 提交。直接比较字形的最终世界矩阵和图片输入，不依赖字形世界版本或只依赖 Label 的版本。覆盖字形回收再使用、颜色富文本、换行、图集切换和平滑变化。

### 遮罩、滤镜、自定义 shader 和离屏

第一期对这些作用域保守禁用复用，继续执行全量路径；开关需要覆盖整个作用域并在退出时正确恢复。若不能可靠识别某类离屏或重入作用域，禁用包含它的整个构建。

两个 Render 实例绝不共享缓存。相同 Render 在已有未完成构建中重入，禁用复用并使关联代次失效。后续逐类放开需要各自独立验收，不依赖“看起来与普通 Image 一样”的推断。

## 9. reset、提交与异常

reset 只开启新构建并归零游标，不能把旧记录直接当成当前有效记录。元数据区分“上次成功完成”和“本轮正在写入”。

新建批次、全量开关切换、异常中断、缓冲被外部修改或作用域不明时，本轮全量写入。未完成记录不能晋升为有效快照。

在实施前先只读检查当前安装版本的 OpenFL：drawTriangles 与 ShaderParameter 是否复制输入、何时读取原数组、数组是否被原地改变。确认生命周期之后再决定使用原缓冲还是轮换存储；不得修改 OpenFL 或 Lime。如果原缓冲不能安全跨构建复用，需要重新核算替代方案的分配与拷贝成本。

## 10. 分阶段实施

### 阶段 A：记录基线与构建生命周期

- 明确普通帧、多舞台、MakerDisplay、离屏、滤镜的调用边界。
- 确认数组提交所有权与有效长度行为。
- 加入可编译移除的调试计数：重绘帧数、图片数、属性写入数、缓存命中数、结构回退数、Graphics 回退数、缓冲构建与提交耗时。
- 保留强制全量构建开关，作为对照和紧急回退手段。

### 阶段 B：普通 Image 稳定前缀

- 实现 per-buffer 记录、构建代次、偏移校验、有效长度和尾部清理。
- 先缓存顶点、UV 和固定索引，再按属性加入 alpha、颜色、ADD、纹理 ID。
- 所有切批与 shader 绑定沿用现有逻辑。
- 图形和特殊作用域按上文回退。

### 阶段 C：字形与兼容验证

- 验证字形对象池和直接写矩阵场景能够正确命中与失效。
- 核对同一对象跨渲染器、同轮多次提交、缓冲缩短再增长。
- 只有正确性和耗时门槛通过后，才考虑默认启用普通 Image/Label 的增量构建。

### 阶段 D：按数据决定扩展

Graphics 不规则片段、特殊作用域复用和更复杂的片段匹配独立处理。第一期结果不足时先定位比较成本、回退比例和 OpenFL 提交成本，不直接叠加更复杂缓存。

## 11. 验证与验收计划

用户已在 2026-11-11 明确授权测试；实现后的实际执行结果与范围记录在验证文档中。下列保留完整验收规划，其中真机和各原生平台尚未逐项执行。

正确性以同一状态的全量输出为参照。建议调试构建提供独立缓冲的影子全量构建，对比顶点、UV、索引、shader 属性、纹理顺序、批次数和有效长度。影子构建不能清除生产路径脏标记、推进 Graphics 命令游标或改变全局渲染状态；先构造同一输入快照再对照。若做不到无副作用，则用确定性输入回放比较两种模式。

至少覆盖：

1. 大量静止图片中仅一个对象移动；整个父容器平移、旋转、缩放或修改 alpha。
2. 开头、中间、尾部对象显隐；增删、换序、重挂与对象回收再用。
3. 纹理数跨越多纹理上限；同一根纹理不同子区域；根纹理替换及尺寸变化。
4. smoothing、NORMAL/ADD、颜色布局、shader 切换与自定义 shader 回退。
5. 直接修改 transform、rect、frameRect、ColorTransform 的分量。
6. 文字变化、富文本、换行、图集替换、字形池复用。
7. Image/Graphics 混排，路径抗锯齿、九宫格、repeat、Spine。
8. 遮罩嵌套、滤镜、cacheAsBitmap、BitmapData.draw、多个 Render 和多舞台。
9. 缓冲长度 1000→10→1000、颜色属性开启→关闭→开启、异常后恢复。
10. 持续结构变化和所有对象每帧运动的低命中场景。

缓冲对比通过后，再检查最终图像和交互相关行为。像素对比采用同平台同设置；涉及抗锯齿时预先规定可接受差异，不以主观目测替代缓冲一致性。

性能统计重绘帧而非混入空闲帧，固定同一场景、平台与构建参数，分别记录预热后的中位数和 P95。调试影子构建不进入性能样本。

建议验收门槛，需在基线采样后确认：

- 正确性矩阵全部通过，无缓存导致的旧帧残留、错图、错色、错位或纹理错绑。
- 静态多数场景的缓冲构建耗时有可重复下降，建议目标至少 15%；这是目标，不是当前实测结果。
- 低命中场景若有超出噪声的持续回退，需优化比较路径或停止默认启用；建议将可重复超过 5% 的退化作为阻断项。
- DrawCall、批次数与全量路径一致，额外缓存内存随活跃批次/槽位有界，尾部引用及时释放。
- 发行构建不含影子构建与逐对象计时开销。

## 12. 第一轮预期文件范围

- hxmaker-openfl：ImageBufferData.hx、Render.hx，以及必要的内部缓存记录类型和调试统计。

## 13. 本轮实施补充

普通 Image/Label 现已默认启用增量构建；可设置 Render.incrementalBufferEnabled=false 使用保留的全量路径。新增低收益批次的自适应退让，完整几何、UV和颜色同时变化的批次暂停采集，首项持续变化时延后恢复，稳定后自动重新采集。特殊作用域与 Graphics 继续全量构建。

源码、编译命令、全量对照范围、96帧像素验证、三轮CPU计时和未覆盖范围均见《渲染缓冲增量构建验证记录.md》。两个仓库仍为本地工作分支，改动未提交或推送。

## 14. 阶段 D 第一轮已完成

Graphics 自身继续全量构建，同批普通图片与文字字形可以复用稳定片段。偏移信息放在批次独立表中，分别验证坐标、索引、逐顶点属性起点；连续布局失配时退让，稳定后恢复。没有增加批次或改变绘制顺序，特殊作用域暂不扩大。

新增测试、96帧像素对照、混排与第一期纯图片对照数据见《渲染缓冲混排增量构建验证记录.md》。第一期后端已在提交 eb50821，本轮新增改动仍在本地分支，未提交或推送。
