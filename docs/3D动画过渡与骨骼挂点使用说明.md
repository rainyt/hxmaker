# 3D 动画过渡与骨骼挂点使用说明

日期：2026-10-16。代码已实现，用户已反馈“测试通过”。记录为动画过渡与骨骼挂点示例的人工验收；未提供可选断言日志或独立性能报告，不将反馈扩写成全部平台与数值回归均已通过。助手未自行编译或运行。

## 接入方式

本功能位于 hxmaker 核心层，不新增 hxmaker-openfl 渲染接口，不修改帧调度。已有 `Assets.loadGlb → GlbAsset.createInstance → Model3D` 加载链路继续使用。

示例采用标准结构：`Main : HxmakerApplication → Game : Stage → test.CharacterRender : Scene`。业务只使用 hxmaker 的显示、事件、资源与生命周期 API，不导入 OpenFL、Lime 或浏览器 API。

```haxe
var assets = new hx.assets.Assets();
assets.loadGlb("assets/robot.glb");
assets.onComplete(_ -> {
    var model = assets.getGlb("robot").createInstance(-1, {lightingEnabled:true});
    scene.root.addChild(model);
    model.animation.play("Idle");
    // 之后在业务状态变化时调用一次，而非每帧重复播放。
    model.animation.crossFade("Walk", 0.2, true);
});
assets.start();
```

在 Scene 的 `onUpdate(dt)` 中显式调用 `model.update(dt)`。场景、阴影通道和绘制回调不会自动推进动画；同一模型每个业务更新只需调用一次。Assets 必须保留到所有使用它的模型、道具和二维图片都销毁之后。

## 播放与过渡

| 接口 | 行为 |
| --- | --- |
| `play(name, loop=true)` | 立即切换，从片段零时刻开始；重复调用会重新播放 |
| `crossFade(name, seconds=0.2, loop=true)` | 平滑过渡，目标从零时刻开始，启动播放 |
| `speed` | 非负有限倍率，默认 1；同时影响片段和过渡，零冻结，不支持倒放 |
| `pause() / resume()` | 冻结或继续片段与过渡时间 |
| `seek(seconds)` | 相对片段起点定位，限制在片段范围内，取消过渡，保持当前播放/暂停状态 |
| `stop()` | 清除片段与过渡，恢复模型初始姿态 |
| `transitioning` | 是否正在过渡 |
| `transitionProgress` | 过渡权重 0～1；无活动过渡时返回 1 |
| `currentName / time / duration` | 始终描述当前目标片段 |

过渡时长为零等价于 `play`，允许重播相同片段。正时长的 `crossFade` 遇到相同目标直接返回，包括暂停和完成后的片段；需要从头重播时使用 `play`。

普通过渡同时推进源和目标片段。源片段不会再派发循环或完成事件。片段缺失的 TRS 轨道回退到模型初始姿态；平移、缩放线性混合，旋转按四元数最短路径插值并归一化。

连续打断过渡时，保存当前实际输出姿态，再从快照过渡到新目标。快照不继续播放，旧过渡不会叠加成无限混合链。初始姿态也可以通过 `crossFade` 平滑进入第一个动作。

两个动作的缩放符号不同时，过渡允许经过零缩放并继续；保留精确局部矩阵及原始缩放轴。GLB 解析器原有的单轨道跨零缩放限制保持不变。

无效名称、负过渡时长、无效速度或 dt 会明确报错。单片段构造方式 `new AnimationPlayer3D(clips, apply)` 保持兼容；独立使用播放器且需要过渡时，需提供可选的 `AnimationBlend3D` 姿态适配。普通业务通过 Model3D 获取的播放器已经配置好适配。

## 播放事件

```haxe
model.animation.addEventListener(hx.events.AnimationEvent3D.FADE_COMPLETE,
    function(event:hx.events.AnimationEvent3D) {
        trace("过渡结束：" + event.clipName);
    });
```

| 事件 | 触发条件 |
| --- | --- |
| `AnimationEvent3D.START` | play 或实际开始一个新目标的 crossFade，初始输出姿态应用之后 |
| `AnimationEvent3D.LOOP` | 当前目标跨越循环边界，最终姿态应用之后 |
| `AnimationEvent3D.COMPLETE` | 非循环片段或零时长片段完成，每次 play/新目标播放最多一次 |
| `AnimationEvent3D.FADE_COMPLETE` | 过渡到达目标，最终目标姿态应用之后 |

事件带 `clipName`、片段相对时间 `time`，以及循环事件的 `loopCount`。大 dt 的多次循环合并为一个事件，loopCount 使用 Float 保存整数计数，避免平台 Int 范围截断。

目标比过渡先结束时，先派发该片段的 COMPLETE，并保持目标终点姿态继续完成过渡。零时长片段在首次有效推进时完成一次；`dt=0`、暂停或 `speed=0` 不推进。seek 不派发播放事件，也不重新开启已经派发过的完成事件；需要新的完整播放周期时调用 play。

同一次更新中的目标事件按 LOOP、COMPLETE、FADE_COMPLETE 顺序派发；零时长片段不产生 LOOP。本批监听中调用 play、crossFade、seek、pause 等命令会延迟到整批事件结束，其他监听仍看到一致的播放器状态和姿态。延迟命令再次触发事件并产生新命令时，新命令留到下一次播放器操作执行，防止递归开始监听无限执行。dispose 立即生效并清空剩余事件和延迟命令。

## 导入节点与骨骼挂点

```haxe
var bones = model.findNodes("Wrist.R");
if (bones.length != 1) throw "需要唯一的右手腕骨骼";
var index = model.getNodeIndex(bones[0]);
var socket = model.createSocket(index, "weapon");
socket.setPosition(0, -0.12, 0.08);
socket.addChild(prop);
```

- `getNodeByIndex(index)` 使用 GLB 原始节点索引；越界、非当前场景节点、已销毁节点或模型销毁后返回 null。
- `findNodes(name)` 返回全部同名的活动导入节点，按 GLB 索引顺序排列。名称可以重复，不静默选择第一个。
- `getNodeIndex(node)` 将借用的导入节点映射回索引；其他模型节点、挂点、非活动节点和已销毁节点返回 -1。
- `createSocket(nodeIndex, name=null)` 在目标下创建普通 Node3D；无效目标明确报错。它不是复制的骨骼，也不增加特殊渲染通道。

导入节点由模型与动画持有，返回引用仅供查询和挂载。当前不支持重排、单独销毁导入骨架节点；修改其局部 TRS 也不构成动画叠加接口。角色整体移动放在 Model3D 或其外层节点，道具位置、朝向与缩放放在 socket 或道具自身。

挂点继承骨骼的节点变换，模型外层变换只应用一次。socket 的局部偏移不由动画覆盖。同一模型可以创建多个挂点，也可以隐藏挂点及其全部附件。

## 所有权与多纹理

Model3D.dispose 沿节点树销毁 socket 及附件。需要保留的附件应在模型销毁前移出；普通 Node3D.remove 只改变父子关系，不销毁对象。

附件 MeshObject 销毁后只解除几何和材质引用；外部创建的 Geometry3D、Material3D 仍由创建者在引用归零后 dispose。模型不会接管附件引用的 Assets 位图。示例顺序为：销毁模型与附件 → 释放道具几何和材质 → 移除二维预览 → 清理 Assets。

最终姿态仍经过现有 CPU 蒙皮与节点矩阵进入渲染器，不为每个角色增加独立的骨骼 uniform。角色和道具继续按程序、公共 uniform、深度、混合及采样兼容性合批；不同状态仍然可以分批。镜像变换会影响绕序兼容键，因此示例打开首个角色镜像时不要求与未镜像角色保持相同批次数。

单片段只采样一次。过渡时的源、目标缓冲按需分配并复用；中断快照属于实例。节点只在姿态变化时更新矩阵与蒙皮，无动画、暂停、零速度和相同姿态不会重复进行蒙皮计算。性能效果尚需同环境实测，不能据代码结构宣称已获得收益。
