# 3D 模型中立资产与优化格式设计

日期：2026-10-17。首版代码已加入，尚未编译或执行数值、浏览器、GPU 和性能验证。按用户要求，测试前先通知，本轮不执行测试。

## 本期范围

当前支持 GLB 2.0 与首版静态 FBX 导入，以引擎中立数据承接模型能力。源文件解析、资产构建、共享资产和模型实例分开；为未来优化发布文件预留数据和版本边界。本期不增加 `.hx3d` 文件编解码和导出命令，也未改变 OpenFL 渲染后端。

实际加载链路：

```text
GLB / FBX 字节
  → ModelImporter：按文件内容识别
  → GlbImporter / FbxImporter：解释各自源格式，FBX 不经过 GLB
  → ModelAssetBuilder：校验、复制输入并生成运行时派生数据
  → ModelAsset：共享只读资产与借用的解码图片
  → Model3D：独立节点、姿态、播放状态、几何和材质
```

运行时不先生成一个自定义二进制文件再读取。当前优化结果存在内存中，首次加载仍需解析源文件。FBX 的具体范围见 [FBX 加载器设计](FBX模型加载器设计与使用说明.md)。

## 使用方式

```haxe
import hx.assets.Assets;
import hx.display3d.Model3D;

var assets = new Assets();
var model:Model3D = null;
assets.loadModel("assets/robot.glb");
assets.onComplete(_ -> {
	var asset = assets.getModel("robot");
	model = asset.createInstance(-1, {lightingEnabled: true});
	scene.root.addChild(model);
	if (model.animation.names.indexOf("Idle") >= 0)
		model.animation.play("Idle", true);
	trace(asset.sourceFormat);
	trace(asset.buildStats);
});
assets.onError(error -> trace(error.toString()));
assets.start();

// 在业务更新中显式推进一次。
// if (model != null) model.update(dt);

// 退出时先销毁实例，再释放加载资源。
// if (model != null) model.dispose();
// assets.clean();
```

`loadModel` 按内容识别 GLB、ASCII FBX 和二进制 FBX，不依赖扩展名，可使用带查询参数的 URL。业务统一使用 `loadModel / getModel / ModelAsset / ModelFuture`。

此前的格式专属加载入口、资产类及 Future 已删除，不提供转发兼容层。同步处理字节时统一使用 `ModelAsset.fromBytes(bytes)`。有图片时，该同步入口只完成解析与构建，业务应通过 Assets 等待图片解码后再实例化。

Assets 原有资源去重及名称规则继续生效，资源键是不含目录、扩展名的文件名；同一 Assets 内不同格式使用相同文件名主体会发生名称冲突，应分别加载或更名。

## 数据与所有权

| 类型 | 职责 |
| --- | --- |
| `hx.model.ModelSourceData` | 各格式导入器输出的中立源数据 |
| `hx.model.ModelAssetBuilder` | 复制源数据，完成与源格式无关的校验与预处理 |
| `hx.model.ModelAssetData` | 可映射到发布文件的纯数据结构及派生信息 |
| `hx.assets.ModelAsset` | 私有持有构建结果，创建共享动画片段和初始姿态，借用已解码图片 |
| `hx.display3d.Model3D` | 每个模型的节点、可变几何、材质、播放与姿态缓冲 |

`ModelAsset.fromSource(source)` 是未来导入器的中立接入点。它进行防御性复制，包括图片字节、节点数组、材质向量、蒙皮矩阵和动画数据。调用方在返回后修改源数组，不会影响资产。此入口不进行 FBX 解析，也不会自动解码图片。

`ModelAssetBuilder.build` 的返回值是可变的 Haxe 结构，供导入器、工具和检查使用；交付后应视为只读。`ModelAsset` 不公开其内部数据引用，只公开统计、警告及动画名称的副本。`buildStats.generatedNormalCount` 按缺失法线的图元数累计；`rigidPrimitiveCount` 是具有单关节刚性权重的源图元定义数，不按节点实例次数累计。

未来图元、骨架和动画引用都通过索引关联。原始图片字节保留在纯数据中；解码位图、动画播放器、运行时姿态和 GPU 句柄不进入发布数据。资产本身不取得图片所有权，图片仍由 Assets 的子资源引用管理。

## 已接入的预处理

| 工作 | 构建阶段 | 实例阶段 |
| --- | --- | --- |
| 缺失法线 | 按原几何算法生成一次，退化面保持向上法线回退 | 复制准备好的法线；业务修改几何后仍可失效重算 |
| 网格局部包围盒 | 计算一次，保存六个边界值；空网格使用空数组 | 直接建立独立 Bounds3D，不再扫描初始顶点 |
| 网格校验 | 校验长度、数值、索引和材质引用 | 私有资产创建路径复制缓冲，避免再次逐顶点校验 |
| 节点层级 | 检查循环、重复父级、场景根节点及 256 层上限，预计算每个场景的父节点优先顺序 | 根据表标记活动节点，更新骨架时顺序遍历 |
| 蒙皮 | 归一化权重并识别全图元单关节刚性绑定 | 直接选择刚性矩阵路径或多权重 CPU 蒙皮路径 |
| 材质 | 把 GLB 的透明模式及双面设置转换为引擎枚举 | 直接赋值，无需解释 glTF 字符串 |
| 动画 | 深拷贝并校验轨道，保留共用时间轴的只读共享 | 共享片段和初始姿态，独立创建可变姿态及播放器 |
| 图片摘要 | 每个图片定义构建一次 SHA-256 | 图片 Future 直接复用摘要键，沿用原有缓存机制 |
| 统计 | 累计顶点、三角形、图元、法线生成及刚性分类数量 | 查询时读取统计副本 |

当前不删除或重排源节点，也不重排顶点和三角形。挂点、节点查询和场景选择仍使用原 GLB 节点索引。位置、UV、索引、法线和动画不做有损压缩；旋转和权重遵循原有归一化约定。

静态网格和刚性蒙皮实例仍保持独立几何数组，业务修改一个实例不会影响其他实例。多权重蒙皮的基础法线借用只读资产，输出法线由实例独立持有；每帧更新后继续刷新几何版本与动态包围盒。`Geometry3D` 的公共构造和 `invalidate` 路径继续校验业务数据，不开放跳过校验的公共构造选项。

统一的蒙皮约定为：模型空间关节全局矩阵乘逆绑定矩阵。蒙皮网格节点自身及其父级变换不再次作用于蒙皮输出，模型外层位置、旋转和缩放仍由显示树应用一次。未来 FBX 导入器需要将源绑定关系转换成这个约定。

## 优化收益的边界

这些改动减少重复实例化和骨架姿态更新中的准备工作，尚未测量加载时间、内存或帧率收益，不承诺具体百分比。

首次 GLB 导入增加了资产复制和预计算；只有一个无光照实例时，提前生成法线未必有利。源解析数据在导入后不再被资产保留，但构建时会出现源数据与新资产数据同时存在的内存峰值。

当前核心几何继续使用 `Array<Float>` 和 `Array<Int>`。静态几何未跨实例共享，多权重蒙皮仍由 CPU 完成，图片仍需解码，后端仍需创建 GPU 资源。尚未实现零拷贝、GPU 蒙皮、压缩纹理、LOD、Morph、PBR 或动画重定向。

GLB 的既有支持子集保持：单个内嵌 BIN、PNG/JPEG 基础色贴图、第一套 UV、三角形、每顶点四个权重及 LINEAR/STEP 节点 TRS 动画。不能把中立化视为完整 glTF 支持。

## 优化发布格式的预留设计

`ModelAssetSchema.DATA_VERSION = 1` 表示内存数据语义版本；`BUILD_VERSION = 1` 表示资产构建算法版本。这两个值已写入构建结果，资产也可公开查询。

数据语义固定为右手系、Y 向上、米制；矩阵使用列向量、列主序，旋转为 x/y/z/w 四元数，动画时间为秒。不同来源应在导入边界完成归一化。

未来 `.hx3d` 应使用独立的文件主次版本，不能把内存结构版本直接当作文件字节协议版本。建议采用固定小端序、文件头、数据块目录和独立数据块：

| 数据块 | 对应当前资产内容 |
| --- | --- |
| 字符串、场景、节点 | 名称、根节点、节点索引、局部变换及层级遍历表 |
| 网格及数值缓冲 | 位置、法线、UV、UInt16/UInt32 索引、关节、权重、局部包围盒和刚性标记 |
| 材质、纹理、图片 | 引擎参数、采样、图片字节及内容摘要 |
| 蒙皮 | 关节节点映射与逆绑定矩阵 |
| 动画 | 片段、节点 TRS 轨道、时间和关键帧值 |
| 版本与特性 | 数据及构建版本、必需特性和可选特性 |

数值缓冲可使用 Float32；当前内存 Float 不强制截断，未来写入时需要检查范围并定义转换精度。索引宽度及关节宽度应按有效范围选择，不直接序列化平台原生数组。包围盒和刚性标记属于派生数据，也需要与实际缓冲的一致性校验；未知必需块拒绝读取，可选块可跳过。

将来增加 `Hx3dWriter / Hx3dReader` 时，由 Writer 写入构建结果；Reader 检查容器长度、块偏移、引用、资源分配上限、版本及派生数据一致性后创建资产。需将可复用的校验从构建器提取出来，避免对发布文件重复生成已有法线或重做全套资产构建。不能仅凭文件声明“已优化”就信任其边界数据。

构建缓存键至少包括源内容、外部依赖内容、导入配置、数据版本及构建版本。本期没有磁盘构建缓存、资源导出命令或文件读取 API，也没有空实现冒充已支持的功能。

## 验证安排

本次只做代码阅读与差异审阅，未执行编译、数值断言、图片解码、浏览器或性能测试。

已准备独立的数据检查入口 `test/model-assets-data.hxml`。用户安排测试后，在仓库根目录执行：

```bash
haxe test/model-assets-data.hxml
```

它检查已知三角形法线和包围盒、源数组隔离、父节点索引较大的层级、多个场景、权重归一化、循环/越界/非有限值等错误，并读取现有恐龙和贴图机器人 GLB，与原解析结果对照。入口不依赖 GPU，但不覆盖运行时加载、图片解码与绘制。

`test/ModelAssetRuntimeChecks.hx` 提供手动集成入口。在配置好 hxmaker 依赖的 OpenFL 项目中加入 `test` 源目录，可调用 `ModelAssetRuntimeChecks.run()`；已通过 `loadModel` 加载图片就绪的资产还可调用 `checkLoadedModel(asset)`。这些入口不自动注册到生产主循环，也尚未编译或运行。

运行时检查覆盖实例隔离、自动法线失效、预计算包围盒、父节点优先蒙皮、挂点、刚性及多权重路径和统一取值。仍需人工确认原有模型外观、贴图、动画过渡、阴影、加载失败清理及退出释放。仓库已有 samples 的模型入口和三维类型 import 已同步迁移，未改变示例玩法，尚未重新编译或测试。参阅 [3D 显示 API 包迁移说明](3D显示API包迁移说明.md) 与 [FBX 对照示例](../samples/3d/fbx-model/README.md)。
