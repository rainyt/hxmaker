# 观测站示例性能深度优化记录

本轮以用户当前的二十只霸王龙为基准，保留独立 Run 动画、游走、PBR、两级阴影、天空、IBL、距离雾和 Bloom，`renderScale` 仍为 0.8。未改变模型、贴图、动画速度和任务流程。

## 实现

- **动态属性分离**：动态模型的位置、法线、切线与 UV、纹理编号、顶点颜色、PBR 参数分开缓存；蒙皮更新只递增形变版本，通用 `invalidate()` 同时递增 `dataVersion`。索引和不变属性不再随每帧动画重传。
- **缓冲提交**：需要更新的动态缓冲替换存储，避免反复覆写 GPU 仍在使用的数据；静态环境保留持久缓存。
- **GPU 蒙皮**：主场景与阴影使用同一组关节矩阵和权重。法线按融合矩阵的逆转置变换，保留负缩放和非均匀缩放行为。
- **CPU 接口兼容**：每次动画仍计算精确 CPU 位置和包围盒，保证裁剪、碰撞和射线拾取不会读取绑定姿态。CPU 法线延迟至读取 `normals` 或 `getNormals()` 时生成，读取不额外派发形变事件。
- **缓存粒度**：阴影模型内按批次判断是否需要更新，刚性关节变化不再连带重传 GPU 蒙皮源几何。材质批次键按版本缓存，着色器查询在一帧内复用。
- **状态及生命周期**：GPU／CPU 切换时清理骨骼属性，包含无 VAO 路径；销毁清理新增缓冲、程序及延迟读取回调，上下文恢复后重新协商能力并重建资源。

库默认仍使用 CPU 蒙皮，示例显式请求：

```haxe
asset.createInstance(-1, {pbrEnabled: true, gpuSkinning: true});
```

当前 GPU 路径面向 WebGL 1／2，需要至少八个顶点属性及足够的顶点 uniform 容量；仅接收满足现有 PBR 顶点参数合批条件的不透明材质，没有辅助贴图、自定义片元代码或显式切线，并要求导入模型的绑定空间和缓存策略符合条件。基础色贴图可以保留。原生后端、能力不足、编译失败、不兼容材质及通用几何修改均保留或回退 CPU 路径。

刚性单关节部件继续使用原有节点矩阵路径，因此动画开启时仍有少量几何上传。GPU 路径不意味着全部 CPU 动画计算消失，也不意味着骨骼矩阵零上传。没有加入跨模型实例化或动画降频。

## 硬件测量

实测环境：Apple M1 Pro，Chrome 155，实际渲染器为 `ANGLE Metal Renderer: Apple M1 Pro`，WebGL 2。CSS 视口 1120×760；DPR 1 的三维目标为 896×512，DPR 2 为 1792×1024。每个 DPR 按修改前／修改后／修改前／修改后交替运行，各两轮。每个场景预热 1.8 秒，再采样 3 秒；下表为两轮均值，动画与阴影均开启，MB 按 1,000,000 字节、KB 按 1,000 字节计。

| 指标 | DPR 1 修改前 | DPR 1 修改后 | DPR 2 修改前 | DPR 2 修改后 |
|---|---:|---:|---:|---:|
| 动画更新 CPU（毫秒） | 4.46 | 1.65 | 4.46 | 1.63 |
| 三维渲染提交 CPU（毫秒） | 5.61 | 3.57 | 5.70 | 3.73 |
| 其中主通道 CPU（毫秒） | 4.05 | 2.25 | 4.12 | 2.40 |
| 其中阴影 CPU（毫秒） | 1.29 | 1.03 | 1.31 | 1.04 |
| 主场景几何上传（MB／帧） | 8.36 | 0.60 | 8.35 | 0.61 |
| 阴影几何上传（MB／帧） | 1.52 | 0.31 | 1.52 | 0.31 |
| 两通道几何上传合计（MB／帧） | 9.88 | 0.91 | 9.87 | 0.93 |
| 骨骼矩阵上传（KB／帧） | 0.00 | 75.93 | 0.00 | 76.44 |
| 主场景 DrawCall | 50.45 | 67.53 | 50.72 | 68.80 |
| 帧时间中位数（毫秒） | 16.70 | 16.70 | 16.70 | 16.70 |

DPR 2 下，动画 CPU 减少约 63%，三维渲染提交 CPU 减少约 35%，几何上传减少约 91%。将骨骼矩阵也计入相关传输后，由约 9.87 MB／帧变成 1.01 MB／帧，约减少 90%。

前后帧时间中位数都约为 16.7 ms，当前采样配置下均约 60 FPS，收益主要体现为 CPU 帧预算余量增加。各轮帧时间 P95 在 16.7～16.8 ms。关闭动画只做刚体移动时，DPR 2 的三维提交 CPU 由约 2.81 ms 变为 3.02 ms，反映了 CPU／GPU 分批的提交成本；定格或隐藏时仍复用已有画面。

原始硬件报告：[DPR 1](2026-10-19-deep-hardware-dpr1.json)、[DPR 2](2026-10-19-deep-hardware-dpr2.json)。

计时口径：`renderCpuMs` 是三维渲染与合成的 CPU 墙钟耗时，包含驱动提交与可能的同步等待；动画时间通过二十个独立模型同步推进测量，预热四十步、采样一百八十步。二者可以用于观察 CPU 帧预算，但不能当作 GPU 执行时间。没有测量 GPU 时间查询。

几何字节数包含顶点与索引，骨骼矩阵字节数单独列出，不包含灯光、相机和模型等其他 uniform。主通道和阴影的索引在稳定动画期间均零上传；关闭动画后保留刚体游走，两个通道均零几何上传。

CPU 与 GPU 路径分开成批会增加 DrawCall，并新增骨骼属性缓冲。这是用少量提交及缓存容量换取更少的逐顶点计算和上传；以实际帧时间及 CPU 耗时评估收益。`geometryCacheBytes` 是缓存预留容量统计，不等于驱动测得的进程显存。

## 复现

在示例目录编译带测试入口的版本：

```bash
HAXE_STD_PATH=/Users/rainy/Documents/SDK/haxe-manager-master/current/std \
  arch -x86_64 lime build html5 -D hxmaker_explorer_checks
```

本机环境的 Haxe 启动路径未自动找到标准库，因此本轮构建显式提供 `HAXE_STD_PATH`；没有修改全局 Haxe 配置。

从 hxmaker 仓库根启动静态服务：

```bash
python3 -m http.server 8733 --bind 127.0.0.1
```

回到示例目录执行：

```bash
node Tools/check_deep.cjs
HXMAKER_GPU=hardware HXMAKER_DPR=1 HXMAKER_VARIANTS=after node Tools/profile_deep.cjs
HXMAKER_GPU=hardware HXMAKER_DPR=2 HXMAKER_VARIANTS=after node Tools/profile_deep.cjs
```

工具默认使用本机 Chrome 和 `/usr/local/lib/node_modules/playwright`。`PLAYWRIGHT_MODULE` 可指定其他 Playwright 安装位置，`HXMAKER_TEST_REPORT` 指定报告文件。

前后对照必须提供修改前另存的 `AwayExplorer.js`，设置 `HXMAKER_BEFORE_JS`，并使用 `HXMAKER_VARIANTS=before,after,before,after`。本轮修改前的编译文件临时保存在 `/tmp/hxmaker-deep-before.js`，未将大型编译产物加入仓库。普通构建执行 `lime build html5`，不会暴露测试命令入口。
