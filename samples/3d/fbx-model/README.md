# FBX / GLB 统一模型加载示例

2026-10-17：代码和原创资源已生成，尚未编译、解析或运行验证，由用户测试。

示例全部通过 `Assets.loadModel → getModel → ModelAsset.createInstance` 加载，运行时按文件内容识别格式。FBX 直接构建中立资产，不经过 GLB；GLB 文件是独立生成的造型对照资源。

## 运行

需要当前工作区版本的 hxmaker、配套 hxmaker-openfl，以及 project.xml 列出的依赖。在本目录执行：

```bash
arch -x86_64 lime test html5
```

如果当前安装的 Haxe/Lime 支持直接启动，也可用 `lime test html5`。本次未执行上述命令。

## 文件与预期画面

| 文件 | 用途 |
| --- | --- |
| `Assets/robot-ascii.fbx` | 默认资源，ASCII FBX 7.4 |
| `Assets/robot-binary-7400.fbx` | 32 位节点记录与 zlib 压缩数组 |
| `Assets/robot-binary-7500.fbx` | 64 位节点记录与 zlib 压缩数组 |
| `Assets/robot.glb` | 同一造型、层级与材质的 GLB 对照 |
| `Assets/checker.png` | 内嵌图片的独立副本，仅供查看贴图方向 |

预期显示两台相同的蓝金色机器人，有身体、头部、四肢、四色面罩和凹多边形徽章。FBX 的源坐标为 Z 向上、厘米单位，归一化后应站立在地面上，高度约两米。FBX 对象 ID 特意超过 JS 安全整数范围，导入器应保持其精度。

按生成器定义，四种资源都应为 8 个网格、14 个图元、78 个三角形、3 份材质和 1 张内嵌图片。FBX 原模型节点之外会增加几何变换辅助节点和坐标归一化根节点；此组对照资源共 18 个节点。以上是生成内容的预期值，尚未通过实际导入核对。

## 手动观察

1. 逐个点击四种格式，检查造型、比例、朝向、颜色与面罩贴图方向是否一致。
2. 左下角为内嵌贴图预览：上排红、绿，下排蓝、黄；面罩上相应方向应一致。
3. 拖动旋转，检查徽章凹口、手臂枢轴位置和方块边缘法线；切换光照与阴影观察外观。
4. 点击“首个实例变色”，只有左侧机器人应变色，右侧仍保留原材质。
5. 重复切换格式、重新加载、销毁并重新进入，检查模型与贴图能否正确释放和恢复。
6. 将自己的静态 FBX 放入 `Assets/custom.fbx`，点击“自有 custom.fbx”。默认不附带此文件，未放入时会显示加载失败。

界面显示来源格式、构建统计和错误；全部导入警告也输出到控制台。示例不自动运行断言，不会把“资源生成完成”当作“加载测试通过”。

## 首版 FBX 边界

支持 ASCII / 二进制 FBX 7.x、Properties70、静态 Mesh、平面简单多边形三角化、基础色、多材质槽、第一层 UV/法线和内嵌 PNG/JPEG 基础色贴图。当前按双面基础材质近似显示，不实现完整 Phong/PBR。

支持常规节点层级、六种欧拉旋转顺序、旋转/缩放枢轴与几何变换；使用归一化根节点完成单位和坐标轴转换。特殊缩放继承只在可准确映射到当前节点树时接受。

骨骼、动画、Morph、约束、分层纹理、外部图片和贴图坐标变换会报错。不要使用带绑定或动画的模型测试静态支持，也不要把错误理解为已经冻结导入。模型可见性、自带相机灯光、顶点颜色等尚未还原，详见 [FBX 设计说明](../../../docs/FBX模型加载器设计与使用说明.md)。

```bash

```

入口比较四种资源的统计、世界空间边界和顶点矩，并覆盖格式识别、64 位 ID、错误版本、变形拒绝和损坏偏移。它不代替浏览器、图片解码与 GPU 画面验证。本次未执行。

## 重新生成资源

在仓库根目录执行：

```bash
python3 tools/generate-fbx-sample.py
```

生成器使用 Python 标准库，写出原创资源，不调用加载器、不进行测试，也不依赖 Blender。资源用于本首版子集的对照，尚未在外部 DCC 软件中验证其兼容性。
