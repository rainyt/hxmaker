# FPS 调试面板

在业务舞台的 `onStageInit()` 中添加面板。应用启动类继续继承 `hx.core.HxmakerApplication`，由启动类初始化业务舞台。

```haxe
override function onStageInit() {
	super.onStageInit();
	var fps = new hx.display.FPS();
	fps.refreshInterval = 0.25;
	fps.detailed = true; // 显示详细信息；默认值为 false
	addChild(fps);
}
```

`new FPS(autoShowTop)`、`label`、`autoShowTop` 和 `refreshInterval` 的接口保持兼容。`refreshInterval` 的单位是秒；设为 `0` 时逐帧刷新。统计始终逐帧采集，面板刷新频率只影响文字和分位数计算。无效或负数刷新间隔按 `0` 处理。

## 精简模式的指标

| 指标 | 口径 |
| --- | --- |
| 帧率 | 采样帧数除以帧间隔总时长，同时显示引擎目标帧率。启动时无需等待满一秒。 |
| 帧间隔均值、P95、峰值 | 相邻两次引擎计时开始之间的墙钟时间。P95 使用排序后向上取整的第 95 百分位样本，反映调度、业务更新和渲染等因素共同造成的帧间隔。 |
| 超预算 | 帧间隔大于目标帧预算的 110% 的样本数／总样本数。保留 10% 容差，减少正常调度抖动的影响；目标帧率无效时显示不可用。 |
| 引擎耗时 | `statsCpuStart()` 到 `statsCpu()` 的平均墙钟耗时。当前 OpenFL 后端覆盖定时任务、流程、舞台更新和渲染提交，不能解释为系统 CPU 使用率或 GPU 执行时间。 |
| 提交绘制 DC | 后端调用统计接口记录的绘制次数，包含下一帧开始前已执行的延迟渲染回调。它不是 GPU 驱动层的完整 DrawCall 测量。 |
| 索引顶点 | 提交索引对应的顶点数量，不是去重后的几何顶点数。 |
| 绘制对象 | 上一轮渲染遍历记录的对象数，不是显示树存活对象总数。按需渲染复用已有画面时，绘制计数可以为零。 |
| JS 堆／运行时堆 | 后端提供的堆内存，使用 MiB 并保留一位小数，不代表应用全部内存。未采样、平台不支持或返回无效值时显示不可用。 |
| 缓存资源、引用总数 | 分别表示已加载缓存条目数和正引用计数之和，两者没有比例关系。 |

帧间隔和耗时采用最近一秒的窗口，最多保留 600 帧。首帧没有有效帧间隔，面板会先显示等待采样。低帧率或长卡顿时，一个样本的帧间隔本身可以超过一秒；保留该样本，以免隐藏长卡顿。暂停恢复和目标帧率变化后重新建立窗口，不混入不同帧预算的数据。

## 详细模式

设置 `fps.detailed = true` 后，额外显示引擎耗时峰值、预算占用、Spine 骨架更新次数、定时任务更新次数、图形和混合滤镜绘制次数、舞台位图池数量，以及渲染配置和舞台尺寸。

堆内存、缓存条目、引用总数的变化量均相对上一次面板刷新，不是泄漏判定或每秒速率。当前后端大约每秒采集一次堆内存，因此部分刷新中内存变化为零是正常现象。启用 `webgl_memory` 时额外显示后端可用的 GPU 内存数据。

## 数据采集与兼容

`ContextStats` 复用现有后端的 `statsCpuStart()`、`reset()`、`statsFps()`、`statsCpu()` 入口，无需调整后端。更新阶段计数会跨渲染前的 `reset()` 保留，在下一次 `statsCpuStart()` 发布只读的 `completedFrame` 快照。已发布快照不会继续修改，面板内所有逐帧计数都来自同一份快照。

`ContextStats.getTiming()` 返回窗口摘要，时间单位为毫秒；`ContextStats.resetTiming()` 可供自定义暂停流程主动重置窗口。面板挂载期间监听所属舞台的激活和失活事件，移除面板时解绑监听。

原来的 `cpu`、`frameUsedTime` 和其他计数属性继续保留。其中 `cpu` 仍是最近 180 次引擎耗时均值除以目标帧预算，`frameUsedTime` 仍使用秒；新面板采用最近一秒的摘要，因此两种时间窗口的结果可以不同。原始计数属性仍随后端更新，读取完整帧数据应使用 `completedFrame`。

所有绘制计数都包含调试面板自身。面板会增加文字处理和绘制负载，正式性能测量应同时比较关闭面板的结果。三维通道耗时、阴影、缓存复用及上传明细继续使用各场景的 `Scene3D.stats`；面板的引擎耗时不包含计时结束之后执行的三维 GPU 回调。
