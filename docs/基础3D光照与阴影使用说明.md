# 基础 3D 光照与阴影使用说明

新增 PBR 因子材质的接口与阶段限制见 [PBR 材质使用说明](PBR材质使用说明.md)。本文以下内容保留基础光照阶段的说明。

> 当前使用总入口：[3D 引擎新手指南](3D引擎新手指南.md)。本文保留分阶段实施记录，其中“当时未测试”等描述属于相应实施时点；后续结果见[验收记录](3D导航验收记录.md)，新包路径与调用方改动见[迁移说明](3D显示API包迁移说明.md)。

当前实现包含主方向光、环境光、Lambert 漫反射、标准不透明及 MASK 物体投影，并提供 PCF4 / PCF9 可选过滤和阴影缓存。实现涉及 hxmaker 与 hxmaker-openfl 两个库，需同步使用包含新接口的源码。

2026-10-18 在自动规划接入前，经用户授权编译并运行过外部 GLB 示例，验证两种 WebGL 路径、可选过滤参数与上下文恢复；本轮自动规划尚未编译或运行，具体范围见[阴影质量与级联使用说明](阴影质量与级联使用说明.md)。历史验收记录仅代表对应时点和项目。

## 在现有 Scene3D 中接入

```haxe
var light = new hx.light.DirectionalLight3D(0xffffff, 0.9);
light.direction = new hx.geom.Vector3D(-1, -2, -1);
light.shadowEnabled = true;
light.shadowMapSize = 1024;
scene.root.addChild(light);
scene.light = light;
scene.ambientColor = 0xffffff;
scene.ambientIntensity = 0.22;

var mesh = new hx.display3d.MeshObject(
    hx.geometry.BoxGeometry.create(),
    new hx.material.LambertTextureMaterial(null, 0xe5b05d)
);
mesh.castShadow = true;
mesh.receiveShadow = true;
scene.root.addChild(mesh);

var floor = new hx.display3d.MeshObject(
    hx.geometry.PlaneGeometry.create(12, 12),
    new hx.material.LambertTextureMaterial(null, 0x6d8096)
);
floor.y = -0.5;
floor.castShadow = false;
floor.receiveShadow = true;
scene.root.addChild(floor);
```

Scene3D 当前只绑定一盏方向光，且灯光必须先属于该场景。direction 表示光的传播方向；方向为 `(-1,-2,-1)` 时，光来自其相反方向。direction 的读取返回副本，修改后需重新赋值。灯光节点的旋转与缩放会参与方向变换，节点位置不改变方向光照明。

方向光使用 color / intensity，环境光使用 scene.ambientColor / ambientIntensity。强度为非负有限值；颜色按显示色值输入，渲染器在线性空间计算并转回显示编码。Lambert 材质仍支持基础纹理、颜色、透明模式与多纹理合批；已有 UnlitTextureMaterial 默认不受光照和阴影影响。

也可修改 `material.lightingEnabled` 切换模式。同一实例内部共享材质的网格会一起改变；不同 GLB 实例的材质独立。自定义片元代码在无光照模式中仍处理原显示色值，在光照模式中处理线性基础颜色，执行位置在光照计算之前。

## GLB 模型

```haxe
var model = assets.getModel("model").createInstance(-1, {lightingEnabled:true});
scene.root.addChild(model);
for (mesh in model.meshes) {
    mesh.castShadow = true;
    mesh.receiveShadow = true;
}
```

实例化选项默认关闭光照，旧调用方式保持原行为。Model3D 持有实例化创建的 Lambert 材质，销毁顺序与原无光照实例一致。

GLB 的 NORMAL 已传入 Geometry3D。刚性单关节路径通过最终世界矩阵的逆转置变换法线；多权重路径混合位置变换并同步变换法线。动画仍只在业务 UPDATE 中更新一次，阴影和主场景读取相同姿态与世界顶点缓存。

## 几何与法线

Geometry3D 增加可选的第四个构造参数 normals，长度应与 positions 相同。不传法线时，只有光照路径调用 getNormals 后才生成法线，不增加普通无光照几何的生成成本。

生成法线按三角形面积累加，并在共享顶点处平滑；需要硬边时应拆分顶点或显式提供法线。调用 geometry.invalidate 后，自动生成的法线会重新生成；显式法线由调用方同步维护。`setNormals(values)` 复制法线数据并使几何失效。直接修改 positions / indices / normals 的内容后仍须 invalidate。

## 阴影配置

2026-10-18 新增自动规划路径，默认 `shadowQuality=BALANCED`。普通场景只需开启灯光阴影并标记投影物；以下旧字段的默认值是请求默认值，未显式设置时实际取景、分辨率和偏差由档位解析。显式参数优先，可调用 `resetShadowOverrides()` 恢复自动配置；`LEGACY` 沿用旧的固定默认策略。本轮自动配置尚未编译或运行，完整说明见[自动阴影说明](阴影质量与级联使用说明.md)。

| 属性 | 默认值 | 含义 |
| --- | --- | --- |
| light.shadowEnabled | false | 请求开启单方向光阴影 |
| light.shadowQuality | BALANCED | 自动质量档位，可选 PERFORMANCE、HIGH、LEGACY |
| light.shadowFilter | ShadowFilter3D.PCF4 | HARD 一次比较；PCF4 四次加权；可选 PCF9 九次帐篷加权 |
| light.shadowAutoUpdate | true | 自动检测阴影变化；false 时手动请求更新 |
| light.shadowMapSize | 1024 | 16～8192 的二次幂，实际尺寸还受设备限制 |
| light.shadowBias | 0.0001 | 归一化阴影深度的固定比较偏差 |
| light.shadowSlopeBias | 0.0005 | 随法线与入射光夹角增加的比较偏差 |
| light.shadowPadding | 0.1 | 自动范围的 XY 边距比例及深度边距比例 |
| light.shadowBounds | null | 可选的世界空间阴影范围，覆盖自动范围 |
| light.shadowDistance | 100 | 相机前向覆盖距离；0 沿用 camera.far，手动范围优先 |
| light.shadowCascadeCount | 2 | 自动取景采用 1 或 2 级阴影 |
| light.shadowCascadeSplit | null | 可选近级联深度比例 (0,1)，null 沿用自动切分 |
| light.shadowCascadeBlend | 0.15 | 两级交界占近级联跨度的比例，0～0.5，0 关闭 |
| light.shadowFilterRadius | 1.5 | 仅 PCF9 使用，0～1.5 阴影纹素，0 为硬采样 |
| light.shadowFadeRatio | 0.1 | 覆盖末端淡出比例，允许 0～0.5 |
| light.shadowNormalBias | 0.5 | 以每级世界纹素尺寸为单位的法线偏移 |
| mesh.castShadow | false | 是否参与阴影投射 |
| mesh.receiveShadow | true | 光照材质是否接收阴影 |

偏差过小可能出现自阴影条纹，过大可能使阴影与物体分离，应结合尺寸和光向调整。当前未使用 polygonOffset。

自动取景优先识别紧凑区域并使用稳定单级范围；较大区域沿用相机局部级联、纹素对齐、交界混合和末端淡出。LEGACY 模式默认覆盖 100 个世界单位，不超过 camera.far。`shadowBounds` 可覆盖自动取景并使用单级固定世界范围。完整参数、资源代价和验证状态见 [阴影质量与级联使用说明](阴影质量与级联使用说明.md)。

自动模式在光空间保守筛选与覆盖区 XY 重叠、且位于接收区域上游的投射物；不会直接套用主相机可见性剔除，因此主相机外但可向画面内投影的物体仍保留。阴影图范围外按无遮挡处理。阴影只衰减方向光贡献，环境光保留，因此阴影区不会被强制压成全黑。

## 能力与限制

- 支持主方向光的单级或两级阴影、HARD、加权 PCF4 和可选 PCF9；不包含 PCSS、多阴影光源、点光源阴影或透明彩色阴影。当前 PBR 与 Lambert 材质均接入主方向光阴影。
- OPAQUE / MASK 且没有自定义 fragmentCode、fragmentUVCode 的网格参与投射；MASK 使用基础纹理 Alpha × 材质 opacity × 顶点 Alpha 与 alphaCutoff 比较，复用纹理区域、过滤、包裹与面剔除配置。相同材质与绕序的 MASK 网格可合批，不同材质拆批。BLEND 和自定义片元处理网格不投射。光照材质可以接收阴影，但未实现透明介质的正确光传输。
- WebGL 1 检测 WEBGL_depth_texture；WebGL 2 使用相应原生能力。无能力、纹理单元不足或阴影 FBO 创建失败时保留光照、关闭阴影，状态通过 scene.stats.shadowStatus 返回。
- 阴影 FBO 创建失败后不会逐帧重复申请；切换尺寸、关闭再开启或上下文重建后可重试。尚无 RGBA 深度编码兼容路径。
- 开启阴影时预留一个公共纹理单元，基础贴图继续合批；上限 16 时基础贴图最多使用 15 个单元，实际还取决于设备和着色器链接回退。
- 光照路径使用第五个属性和 13 个浮点数/顶点；无光照路径保持原有四属性和 10 个浮点数布局。状态守卫按本帧实际需要保护属性，不为每个 pass 重复创建完整状态快照。

## 统计与资源

drawCalls / triangles / uploadedBytes 继续描述相机主场景，compositeDrawCalls 描述二维合成。新增：

- shadowDrawCalls、shadowTriangles、shadowUploadedBytes：最近一次场景重绘中阴影通道的实际提交与上传统计，命中缓存时为零。
- shadowCacheHit：最近一次场景重绘是否复用阴影；整场景直接复用合成画面时，保留最近一次重绘结果。
- shadowMapSize：每级实际边长；shadowMapBytes：全部级联深度与颜色附件的估算占用。新增 shadowCascades、shadowDepthBits、shadowWorldTexels 报告级联数、深度位数和世界纹素尺寸，实际驱动占用可能不同。
- shadowStatus：实际启用或降级原因；按钮开启表示请求开启，不能代替此状态。

全局 ContextStats 同时计入主场景、阴影和最终合成。阴影目标属于 Scene3D 对应的后端渲染器；关闭阴影或没有可用投射/接收对象时释放目标，场景销毁时释放阴影程序与缓冲。上下文丢失时丢弃句柄，恢复后重建；既有二维上下文恢复问题尚未在本轮验证或解决。

动态场景按各级实际投影物状态和阴影矩阵判断是否重绘对应级联；自动取景随相机更新。scene.autoRender=false 且场景、灯光等未失效时复用场景结果，详细缓存规则见后文。


建议顺序：

1. 切换到方块场景，关闭旋转，分别关闭阴影与光照，确认“光照开启、阴影关闭”仍有表面明暗。
2. 开启地面、光照和阴影，切换光向，观察投影方向改变；切换 512 / 1024 比较硬阴影边缘。

4. 切换多纹理、地面可见性、重新加载，检查画面与底部状态。普通基础 3D 示例应继续可用。
5. 如需运行 CPU 数值断言，增加 `-D hxmaker_glb_checks`。其新增检查覆盖法线生成与失效、非均匀/负缩放、蒙皮法线、正交投影和 GLB 光照实例；这些断言不验证 GPU 阴影质量。

## 性能优先配置（2026-10-17）

```haxe
light.shadowEnabled = true;
light.shadowMapSize = 512;
light.shadowFilter = hx.light.ShadowFilter3D.HARD;
light.shadowAutoUpdate = true;

// 按需切换为四次比较；硬阴影程序不包含这些额外采样。
light.shadowFilter = hx.light.ShadowFilter3D.PCF4;

// 可选高质量模式；省略这些赋值时仍使用 PCF4 和自动切分。
light.shadowFilter = hx.light.ShadowFilter3D.PCF9;
light.shadowFilterRadius = 1.5;
light.shadowCascadeSplit = 0.4; // null 恢复默认自动切分
light.shadowCascadeBlend = 0.2; // 0 关闭交界混合

// 镂空纹理自动按轮廓投影，无需额外的轮廓开关。
mesh.material.alphaMode = hx.material.AlphaMode3D.MASK;
mesh.material.alphaCutoff = 0.5;
mesh.castShadow = true;

// 可选手动模式：冻结已生成的阴影，业务在需要时主动请求更新。
light.shadowAutoUpdate = false;
light.requestShadowUpdate();
```

自动模式比较投影物版本、世界矩阵及实际阴影矩阵。相机运动使投影改变时重绘；纹素对齐后矩阵完全一致时可以复用，并同步级联选择与淡出参数。固定世界范围不会仅因相机移动而重绘。无关远处投影物不参与缓存快照；仅改变接收物不会要求重绘投影内容。首次启用、图集布局变化、目标重建及上下文重建后仍会生成阴影。

手动模式保留已有阴影、光源投影矩阵和生成时的级联选择相机，模型或光向变化不会自动更新该贴图；应调用 requestShadowUpdate 恢复同步。关闭阴影或没有投射物、接收物时会释放目标，重新满足条件后重新生成。

原地修改纹理像素或纹理区域后，应调用 material.invalidate() 让自动模式检测变化；手动模式还需 requestShadowUpdate()。动态几何继续遵循 geometry.invalidate() 约定。

缓存减少静态投影的绘制与上传，不会省略动态投影物的更新。PCF4 / PCF9 仅软化阴影边缘，不模拟随距离变化的真实半影。PCF9 的采样成本更高，显存占用不变；移动设备表现仍需目标设备验证。

后续验证应覆盖：自动取景随相机变化而失效、固定范围仅移动相机时缓存命中、远离物体不扩大 XY、镜头外上游物体仍投影、动画和材质变化时失效、手动更新、纹理轮廓与顶点透明度、三种过滤切换、多场景和上下文重建。已有示例验证范围见专题文末。

自动取景数值检查入口为 `test/DirectionalShadowFitChecks.hx`，覆盖远离物体、镜头外投影物、深度扩展、相机移动、纹素对齐覆盖和参数校验。2026-10-18 已编译并在浏览器运行通过，还增加可选过滤参数和级联切分的校验。
