# 霸王龙群体性能验证

观测站新增用户提供的 `dinosaur.glb`，共 10 个独立骨骼动画实例，合计 63300 个顶点、27360 个三角形、200 个骨骼关节。源资产加载一次，实例的动画、蒙皮与几何分别维护。所有实例默认播放错开相位的 Run 动画，并投射、接收阴影。

## 操作

- `G`：行走、定格、隐藏之间切换。定格冻结位移和动画；隐藏也停止更新。
- `Y`：独立切换霸王龙投射阴影。
- `U`：独立切换骨骼动画，关闭时保留刚体游走。
- `T`：原有多纹理开关。

界面显示群体状态、最近重绘的阴影上传量、阴影 CPU 提交耗时和几何重建级联数。CPU 数据不是 GPU 执行时间。隐藏或定格后场景可以复用已绘制画面，上传量等绘制计数可能沿用最后一次重绘。

游走采用固定种子的伪随机目标，限制在庭院范围内，避让静态碰撞代理，并保留个体间距。这是视觉游走与压力测试，不给恐龙增加玩家碰撞体或完整寻路、战斗逻辑；视口外的龙也推进动画。

## 检查结果

`test/tools/run-dinosaur-browser.cjs` 检查模型数量、移动与动画推进、定格和隐藏、独立动画与阴影控制、销毁重进，并分别采集隐藏、定格、刚体移动、刚体移动加阴影、骨骼动画无阴影、骨骼动画加阴影六种负载。

采样环境是 Chrome 无头浏览器的 SwiftShader 软件 WebGL，相同 1120×760 视口、固定初始相机，保留现有阴影、Bloom、距离雾与分辨率。各组顺序采样，角色位置会继续变化；用于定位趋势，不能代替同路线的硬件 A/B 测试。

| 负载 | 平均阴影几何上传/采样帧 | 几何重建级联数/采样帧 |
|---|---:|---:|
| 隐藏、定格 | 0 | 0 |
| 刚体移动，不投射阴影 | 0 | 0 |
| 刚体移动，投射阴影 | 2646204 B，约 2.52 MiB | 2 |
| 骨骼动画，不投射阴影 | 0 | 0 |
| 骨骼动画，投射阴影 | 2646204 B，约 2.52 MiB | 2 |

结果确认：动态投射物使两个级联持续重建、上传，静态阴影几何缓存不能把角色与静态世界分开。软件 WebGL 中开启龙阴影的主要热点是 `bufferSubData`，包含驱动同步等待，不能将其耗时推断为用户显卡耗时。关闭龙阴影后，主要热点转为主场景的顶点整理、TypedArray 复制和法线变换；骨骼动画还增加蒙皮更新。

下一步应优先分离静态与动态阴影几何，再评估动态角色局部顶点缓冲和跨级联复用；本次保留现有引擎路径以便复现和测量问题，没有提前修改后端来掩盖负载。

完整采样记录：`samples/3d/away3d-explorer/Validation/2026-10-19-dinosaurs.json`。运行该专项需先在示例目录用 `lime build html5 -D hxmaker_explorer_checks` 构建；交付预览使用普通构建。


## 用户设备的实际录制

`Trace-20261019T092943.json`（DPR 2）记录了 263 次帧回调，回调区间约 6.76 秒，平均约 38.7 FPS。回调平均 25.54 ms、中位数 24.63 ms、P95 29.78 ms，全部回调超过 60Hz 的 16.67 ms 预算。

CPU 采样折算到每个回调：阴影通道约 10.0 ms，主场景约 9.3 ms，群体更新（含动画、蒙皮）约 3.4 ms；GC 自身采样约摊销 1.2 ms。通道包含其子调用，不能再次叠加子项。阴影几何循环自身累计约 2.01 秒，主通道顶点整理自身约 1.03 秒，是主要 CPU 热点。

实际录制中 `bufferSubData` 自身累计仅约 28 ms，远低于软件 WebGL 采样中的等待开销。因此，真实机器的优化重点首先是减少 CPU 重组、复制与重复变换，而不能根据软件结果直接将瓶颈认定为 GPU 缓冲同步。优先静态/动态阴影几何分离，并让动态蒙皮数据尽可能跨级联复用；随后处理主场景持久几何缓冲。CPU 蒙皮不是唯一或最大的耗时项，单独优化蒙皮无法解决全部降速。

模型无贴图，只有 8 种材质颜色，所以多纹理开关不是解决霸王龙负载的主要手段；它仍可用于对照整个世界的纹理批次。

实际录制汇总：`Validation/2026-10-19-dinosaurs-hardware-trace.json`。本次只建立可复现压力场景并保存分析，没有修改渲染后端。
