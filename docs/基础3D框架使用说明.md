# 基础 3D 框架使用说明

## 当前状态

基础代码已加入 hxmaker 和 hxmaker-openfl。2026-10-16 已完成 HTML5 示例编译和浏览器基础交互验证，具体结果见《基础 3D 框架验证记录》；尚未完成全部平台和边界场景验收。

当前后端适配参考本地 OpenFL 9.2.8 与 Lime 8.0.2 开发源码；需同时更新两个仓库。现有 IRender 接口未增加必选方法，OpenFL Render 通过额外的 IScene3DRenderer 接入三维场景。

## 创建场景

```haxe
var scene = new hx.display.Scene3D(640, 360);
scene.x = 20;
scene.y = 40;
Hxmaker.topView.addChild(scene);

var camera = new hx.display.Camera3D();
scene.root.addChild(camera);
scene.camera = camera;
camera.setPosition(0, 2, 6);
camera.lookAt(new hx.geom.Vector3D());

var material = new hx.material.UnlitTextureMaterial(assets.getBitmapData("crate"));
var mesh = new hx.display.MeshObject(hx.geometry.BoxGeometry.create(), material);
scene.root.addChild(mesh);
```

Scene3D 继承 DisplayObject，但不是二维容器。只通过 root 接收 Node3D；MeshObject 和 Camera3D 继承 Node3D，不能直接加入普通 Sprite 或 Stage。

width、height 是场景的逻辑视口尺寸。设置它们改变视口及相机宽高比；scaleX、scaleY 改变最终二维合成缩放，不自动增大目标纹理。需要更高清晰度时设置 renderScale，它会再乘上后端设备像素比。

采用右手坐标，X 向右、Y 向上，相机默认朝向 -Z。旋转单位是度，顺序为 X、Y、Z。支持父子变换与负缩放；零缩放模型跳过渲染与拾取。

## 材质与多纹理

```haxe
var material = new hx.material.UnlitTextureMaterial(texture, 0xffffff);
material.alphaMode = hx.material.AlphaMode3D.BLEND;
material.opacity = 0.5;
material.cullMode = hx.material.CullMode3D.NONE;
```

OPAQUE 忽略贴图和模型透明度，写入不透明表面；MASK 根据 alphaCutoff 丢弃透明部分，并写入不透明表面；BLEND 使用预乘 Alpha 混合，关闭深度写入并保留深度测试。透明模型以包围盒中心从远到近排序，交叉透明面仍有局限。

默认无光照材质。texture=null 时使用共享白色贴图。支持普通 BitmapData 和没有裁边还原信息的矩形图集区域；不支持旋转图集和分离 Alpha 压缩纹理。新增 textureWrapU / textureWrapV，可设置 TextureWrap3D.CLAMP、REPEAT 或 MIRROR；重复与镜像当前要求无填充的二次幂整图，不接受图集区域。

`smoothing` 控制基础层放大过滤，`textureMinSmoothing=null` 表示缩小时沿用相同设置，也可单独指定。过滤和包裹参数进入合批兼容键，贴图不同但采样一致的网格仍可合批。尚未生成 mipmap。

GLB 材质使用 `colorMultiplyLinear=true`，在线性空间计算贴图与基础色相乘；手工创建的无光照材质默认保留原显示空间相乘行为。光照材质本来就在线性空间计算。新增 `uLinearBaseColor` 是内置 uniform，不能通过 setUniform 覆盖。

一个批次通过多个 sampler2D 与顶点 textureId 选择贴图。兼容程序、公共 uniform、采样、深度、混合和绕序的网格可以合批。关闭 `scene.multiTextureEnabled` 后走单槽位路径；不会改变现有二维多纹理开关。

默认使用 CPU 世界坐标顶点缓存和索引合并。槽位数按设备能力选择，上限 16；程序编译失败时降低槽位数重试。单批次最多 65,535 个顶点、196,605 个索引，超大网格按三角形自动分批。

## 自定义片元效果

```haxe
material.fragmentDeclarations = "uniform vec3 uTint;";
material.fragmentCode = "color.rgb *= uTint;";
material.setUniform("uTint", [1.0, 0.8, 0.6]);
```

fragmentCode 在基础贴图采样和模型颜色应用后执行，此时 color 为未预乘颜色；之后框架处理 Alpha 模式并输出预乘结果。代码可读取 vUV 和 vColor。

可声明浮点标量、vec2、vec3、vec4 和 mat4 uniform，值长度分别为 1、2、3、4、16。不支持自定义 sampler、整数 uniform、uniform 数组或顶点程序替换。缺省活动 uniform 在每批次重置为零，不继承上一份材质。保留 uSampler 前缀、uViewProjection、uAlphaMode、uAlphaCutoff 等内置名称。

不同片元代码使用不同程序；代码相同而 uniform 值不同也会分批，避免颜色或参数串用。不同 texture 和编码进顶点的 color、opacity 可以保持合批。

## 动画与失效

```haxe
scene.addEventListener(hx.events.Event.UPDATE, function(_) {
    mesh.rotationY += Hxmaker.engine.dt * 45;
});
```

Scene3D 默认 updateEnabled=true、autoRender=true，每帧重绘三维目标。静态场景可设置 autoRender=false；修改节点、几何或材质会通知场景。直接改变 Geometry3D.positions、uvs、indices 后必须调用 geometry.invalidate()。

相机投影参数与场景设置在场景更新中检查。直接修改源位图像素后需要调用 scene.requestRender()；业务更新只在 UPDATE 中执行，GPU 绘制回调不会再次推进动画。

Node3D.getWorldMatrix() 返回副本；修改返回矩阵不会改变节点。setLocalMatrix() 可保存精确仿射变换，相机 lookAt() 使用此路径抵消父节点变换。之后修改旋转或缩放会重新使用分解后的标量变换，剪切分量不再保留。

## 拾取

```haxe
scene.addEventListener(hx.events.MouseEvent.CLICK, function(event:hx.events.MouseEvent) {
    var hit = scene.pick(event.stageX, event.stageY);
    if (hit != null) trace(hit.object.name);
});
```

返回最近几何命中的对象、世界位置、从近裁剪面射线起点计算的世界距离、三角形编号和模型局部 UV。先检查包围盒，再在网格局部进行三角形求交，最终按世界距离比较；包含近远裁剪检查。

首版拾取双面几何，不读取纹理 Alpha。普通鼠标事件由 Scene3D 的二维矩形接收，三维节点不会自动进入原有事件冒泡链。通过鼠标事件调用 pick() 可以利用已有二维 UI 遮挡；直接调用 pick() 不检查覆盖 UI 或祖先遮罩。

## 资源与统计

MeshObject 持有几何和材质的引用；调用 mesh.dispose() 只解除引用和监听，不释放共享资产。Geometry3D、Material3D 仍被模型引用时调用 dispose() 会报错。

Scene3D.dispose() 销毁三维节点树并通知各后端释放自己的离屏目标、缓冲与程序。源 BitmapData 仍由 Assets 或创建者释放。移出舞台不会立即释放场景 GPU 资源，以免二维后端重建显示树时反复分配；不再使用的场景应显式 dispose()。

scene.stats 提供最近三维重绘的 drawCalls、triangles、visibleMeshes、culledMeshes、uploadedBytes、textureSlots、targetBytes 和 splitReasons。compositeDrawCalls 表示最后一次回调的最终纹理合成次数，当前为 1。

新增可选 `scene.profilingEnabled`，默认 false。开启后，stats 的 renderCpuMs、shadowCpuMs、mainCpuMs、compositeCpuMs、stateCpuMs 记录完整回调及相应阶段的 CPU 墙钟毫秒数，不是 GPU 时间。renderId 在每次成功回调后递增，redrawId 仅在主场景重绘时递增，redrawThisFrame 表示最近回调是否重绘，profileReady 表示该回调是否开启计时。targetWidth / targetHeight 记录实际目标像素尺寸。

GL 状态优化增加 stateFlushCpuMs、stateSnapshotCpuMs、stateRestoreCpuMs、samplerRestoreCpuMs，分别表示 OpenFL 提交、状态快照、普通状态恢复和共享采样恢复；四者之和为 stateCpuMs。按需快照可能发生于主通道内部，不能再与 mainCpuMs 相加计算总耗时。stateQueryCount、stateTextureSlots 记录保护器查询数量与保存的纹理槽数，stateCompositeOnly、stateVao 标明实际保护路径。跨旧版本优先比较完整 renderCpuMs，避免状态细分口径变化造成误判。

旧 drawCalls 等统计仍描述最近重绘；读取本帧实际提交时需结合 redrawThisFrame，静态复用帧的主场景批次和上传量应按零处理。统一采样与报告格式见[引擎验收与性能基线示例](../samples/engine-acceptance/README.md)，该新增统计与验收入口本轮尚未运行。

targetBytes 按颜色 4 字节加深度 2 字节估算，不含驱动对齐与临时资源。三维批次与最终合成都计入全局 ContextStats，现有 Render.drawCall 属性仍主要描述二维构建批次。

## 后端边界与验证

首版只接入 OpenGL/WebGL。Scene3D 及其祖先的特殊二维 blendMode、自定义二维 shader、filters，以及后端 cacheAsBitmap 暂时明确报错。多个 Scene3D 各用独立深度目标，只按二维显示顺序合成；不会相互穿插。

GPU 状态适配集中在 RenderStateGuard3D，负责恢复程序、目标、视口、纹理、顶点属性、深度、混合和父级裁剪。基础示例中三维前后的二维文字与图形已正常显示，共享纹理采样状态已单独验证。主动丢失上下文后，三维资源可重建，但本地工具链的二维内容恢复失败，纯二维对照也能复现；复杂 UI 遮罩仍需单独验证，不能据基础示例认定全部兼容。

针对二维恢复失败，当前已补充 Engine 统一恢复入口、字形重建和缓存失效，并修复本地 OpenFL 的 Shader、Graphics、BitmapData 离屏渲染器与缓冲的设备归属。恢复后保留 CPU 字形像素的路径已由用户在 Safari 纯二维示例验证：4 轮恢复及最终人工通过，11 个文字全部准备完成。混合恢复需单独记录；实现位置与独立诊断入口见 [二维上下文恢复修复说明](二维上下文恢复修复说明.md)。

## 渲染查询缓存

设备能力与尺寸上限按上下文缓存，着色器活动 uniform 和位置按程序缓存；上下文失效时重新初始化。共享纹理通过 OpenFL 当前采样状态保存、临时修改和恢复，默认不逐帧调用 getTexParameter。程序缺省 uniform 仍逐批清零。

这一协议要求共享纹理的采样参数通过 OpenFL 设置。如果外部原始 GL 代码直接修改采样参数，应使用 `-D hxmaker_3d_full_state_queries` 启用完整采样参数查询兼容路径。

当前状态保护按实际路径保存：需要三维重绘时保护目标、视口、深度与裁剪等状态；仅合成已有纹理时采用轻量保护，并跳过网格遍历。纹理槽在首次绑定或上传前保存。HTML5 优先使用独立 VAO 隔离主通道、阴影、合成的顶点输入，退出时恢复父级 VAO；不支持时回退到逐属性保存恢复。原生平台本轮保留逐属性保护。上下文丢失后丢弃 VAO 句柄，下次绘制重建，场景销毁时删除有效上下文内的 VAO。

`-D hxmaker_3d_legacy_state_guard` 关闭轻量保护、VAO 与按需槽位保存，供同源码对照；`-D hxmaker_3d_no_vao` 单独关闭 VAO，用于验证回退路径。两者均不改变多纹理合批及帧调度。本轮优化仅完成实现与静态审阅，尚未编译或运行；测试与数据记录方法见 [引擎验收示例](../samples/engine-acceptance/README.md)。

`-D hxmaker_3d_profile` 仅诊断构建输出完整三维回调的墙钟耗时；普通构建无计时。回归示例与数据见 [渲染优化记录](基础3D渲染优化记录-20261016.md)。
