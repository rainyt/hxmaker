# 混合模式直接渲染修复说明

`hxmaker-openfl/samples/Source/test/BlendModeRender.hx` 创建四张图片，分别使用 NORMAL、ADD、MULTIPLY、SCREEN。MULTIPLY 经由 `BlendModeFilter` 截取背景、绘制源图片，再使用自定义 Shader 合成。

## 修复的协议错误

当前使用的 OpenFL 位于 `/Users/rainy/Documents/haxelib-self/openfl`。其 `Shader.__enableGL()` 跳过 uniform 位置为 null 或负数的输入，给剩下的活动 sampler 连续分配纹理单元。活动 sampler 即使没有提供图片，也仍然占用一个单元。

原来的 `DirectBatchRenderer.drawNative()` 按 `ShaderBuffer` 的原始数组下标绑定纹理。GLSL 混合模式声明了未使用的 `uSampler16`，编译后的活动输入列表出现空位，两种编号因此错开。另一个问题是空图片被直接跳过，保留了之前批次或离屏目标的纹理绑定。

现在 sampler 的 uniform 编号继续交给 OpenFL，实际纹理绑定使用相同的活动输入顺序：

- 未使用的输入不占单元，也不解析或上传图片。
- 活动输入按连续编号绑定，图片、过滤和环绕设置始终从对应的快照下标读取。
- 没有图片的活动输入保留编号，并显式解绑该单元。
- 修改绑定前仍经由状态保护器保存旧值，以便绘制结束后恢复。

没有删除 Shader 中的额外声明，也没有改变普通图片的直接提交路径。
