# 基础 3D 示例

2026-10-17 入口整理：`Source/Main.hx` 继承 `HxmakerApplication`，通过 `init(GameStage, width, height)` 初始化业务舞台；场景、资源与更新逻辑位于 `Source/GameStage.hx` 的 `onStageInit()` 及其辅助方法中。本次尚未编译或测试。

此示例使用程序生成的棋盘格贴图，不需要下载外部模型或图片。

依赖当前开发版本的 hxmaker 和 hxmaker-openfl。示例配置列出的 haxelib 必须已安装，并指向包含本次实现的源码。

在本目录使用以下命令编译并启动 HTML5 示例：

```bash
arch -x86_64 lime test html5
```

2026-10-16 已使用上述命令通过编译，并在浏览器中验证旋转、贴图、透明、二维文字、模式切换和点击拾取。当前示例开启多纹理为 2 个三维批次、最多 13 个纹理槽位；关闭后为 14 个批次、1 个槽位。两种模式均绘制 158 个三角形，最终场景纹理合成另计一次绘制。

项目由 OpenFL 间接引入 Lime，不要再在 OpenFL 之后重复声明 Lime，否则本地工具链可能选用错误的应用入口模板。启动服务器需要允许监听本地端口。

示例包含十二个共享几何的模型、十二张独立贴图、一个地面、一个透明模型及覆盖在场景上方的文字。点击标题可切换三维多纹理合批；点击模型可查看拾取结果。不同设备的槽位数可能不同，实际批次数以界面显示为准。

重点观察：模型深度遮挡、相机运动、父子节点旋转、纹理编号正确性、透明物体和三维前后二维文字的显示情况。多纹理模式应在材质与容量兼容时减少批次数，不能预设所有设备上都是一次绘制。

使用说明见 [基础 3D 框架使用说明](../../../docs/基础3D框架使用说明.md)。

详细验证范围见 [基础 3D 框架验证记录](../../../docs/基础3D框架验证记录.md)。

## 渲染诊断

仅在需要验证时启用以下参数（可用 build 复用已有服务器，或用 test 启动）：

```bash
# 完整三维回调计时，预热 120 次后每 240 次输出一组
arch -x86_64 lime test html5 -D hxmaker_3d_profile

# 共享纹理采样状态断言、自定义 uniform 红绿黑对照及上下文恢复按钮
arch -x86_64 lime test html5 -D hxmaker_3d_regression

# 外部原始 GL 代码绕过 OpenFL 缓存时的完整查询兼容路径
arch -x86_64 lime test html5 -D hxmaker_3d_regression -D hxmaker_3d_full_state_queries

# 关闭全部 Scene3D 绘制，隔离二维上下文恢复问题
arch -x86_64 lime test html5 -D hxmaker_3d_regression -D hxmaker_3d_regression_2d_only
```

诊断构建在三维前后绘制同一张二维贴图，每 30 帧交换平滑开关；连续 120 帧状态一致时输出 PASS。为了覆盖 NEAREST，诊断路径关闭 OpenFL 的自动放大平滑。右上角三个模型共享同一程序，分别传红、绿、缺省参数，预期显示红、绿、黑。底部文字可触发 WebGL 上下文丢失与恢复。普通构建不包含这些探针，也不计时。

当前本地工具链存在上下文恢复后二维内容消失的问题；纯二维对照亦可复现，恢复验证尚未整体通过。数据和边界见 [渲染优化记录](../../../docs/基础3D渲染优化记录-20261016.md)。不要同时开启计时和回归探针来比较性能。
