# 3D 引擎第二阶段设计方案

日期：2026-10-16。状态：里程碑一“动画过渡与骨骼挂点”已由用户反馈测试通过，见[使用说明](3D动画过渡与骨骼挂点使用说明.md)；里程碑二“相机与三维交互”代码与独立示例已加入，等待用户验收，见[使用说明](3D相机控制与交互使用说明.md)；里程碑三仍为设计提案。

## 阶段目标

第一阶段已经建立了基础渲染、Assets 加载 GLB、贴图、骨骼动画、光照、硬阴影、多纹理合批，以及性能统计与上下文恢复能力。用户已确认现有示例测试正常，可以进入下一阶段。

第二阶段目标是让这些能力组合成可用于小型项目的角色与场景框架：角色能够平滑切换动作、挂载道具、接受选择与移动指令，相机能够跟随和环绕，场景能够反复进入和退出。

本阶段继续使用 `Scene3D : DisplayObject`、`Node3D` 三维节点树和现有多纹理渲染器。保持当前帧调度设计，更新仍由业务 UPDATE 显式驱动。

## 现状与设计依据

| 能力 | 当前实现 | 第二阶段安排 |
| --- | --- | --- |
| 三维视口、节点树、相机 | 已有，支持二维嵌入和独立深度目标 | 保留结构，补相机控制器 |
| 多纹理合批 | 兼容材质与渲染状态的网格可合批 | 作为持续验收项 |
| GLB 与资源实例 | Assets 加载，共享源贴图，运行时几何、材质和播放状态按实例创建 | 保留所有权规则，补稳定节点查询 |
| 动画 | 单片段播放、暂停、定位、循环；切换直接应用新姿态 | 增加过渡、播放速度和播放事件 |
| 蒙皮 | 通用 CPU 蒙皮写入实例 Geometry3D；单关节刚性网格更新节点矩阵 | 先复用，再按实际负载决定优化 |
| 拾取 | Scene3D.pick，包围盒初筛与逐三角形检测 | 复用并扩展射线查询、过滤和交互适配 |
| 相机操作 | Camera3D.lookAt、screenRay 等数学能力 | 增加跟随、环绕和缩放 |
| 场景组织 | 可自行建立、销毁节点，Procedure 可管理业务流程 | 提供完整示例和明确更新、释放顺序 |

源码核对：当前 CPU 蒙皮直接修改 `mesh.geometry.positions` 并调用 `invalidate()`，刚性蒙皮通过网格矩阵实现，因此现有拾取读取的是当前姿态数据。不能把“动画模型拾取仍使用绑定姿态”列为已确认缺陷；第二阶段应覆盖动画姿态拾取的回归。

已有性能基线显示，多纹理可以显著减少角色批次；高密度动画还包含蒙皮、顶点整理及上传成本。因此功能扩展与性能优化分开推进，不能用 DrawCall 数量单独衡量角色承载量。参见[最终报告分析](../samples/engine-acceptance/Baselines/2026-10-16-最终分析.md)。

## 架构分工

| 层级 | 职责 | 预计改动位置 |
| --- | --- | --- |
| 引擎核心 | 姿态求值与混合、节点查询与挂点、射线查询、相机数学控制 | hxmaker 的 hx.animation3d、hx.display、hx.geom，以及拟新增 hx.controls3d |
| 输入适配 | 将现有二维鼠标或触摸事件转换为相机和选择指令 | hxmaker 可选适配类；不绑定具体 OpenFL 输入对象 |
| 渲染后端 | 消费最终几何、节点矩阵、材质，维持深度、阴影和合批 | 首个里程碑预计不修改 hxmaker-openfl 必选接口 |
| 项目示例 | 移动目标、待机/行走状态、选择反馈、UI 和 Procedure 流程 | samples/interactive-character，拟新增 |

角色移动规则、战斗状态、寻路与具体按键配置留在项目或示例中。暂不引入通用 ECS、物理世界或新的全局更新器。

## 里程碑一：动画过渡与节点挂点

这是建议首先实施的范围，可独立交付并由用户验收。

### 动画接口

保留现有 `play / pause / resume / seek / stop / update` 接口，本轮增加：

```haxe
// 已加入代码，用户已反馈示例测试通过。
model.animation.speed = 1.0;
model.animation.crossFade("Walk", 0.2, true);
```

`crossFade(name, duration, loop)` 的契约：

- 片段不存在、时间无效等错误在修改播放状态前报告；过渡时长为零等价于立即播放。
- 目标片段从零开始；正常过渡期间源与目标均按 speed 推进。首版 speed 只接受非负有限值，零表示冻结，不支持倒放。
- 平移和缩放线性混合，旋转使用归一化四元数最短路径插值。缺失轨道回退到模型初始姿态，避免继承上一个动作的残留值。
- 连续中断过渡时，以当前混合姿态快照作为新过渡起点，旧过渡不继续形成混合链。此时起点姿态冻结，目标继续推进，保证切换瞬间连续并限制求值成本。
- 暂停同时冻结播放和过渡；seek 取消过渡并定位到目标片段；stop 取消过渡并恢复初始姿态。
- 同一目标正在播放或过渡时，crossFade 默认不重启；需要重播时继续使用 play。

内部将现有 `applyPose(clip, time)` 拆为“采样到可复用 Pose3D → 混合 → 应用节点 → 计算骨架与蒙皮”。单片段路径保留直接求值，避免为未使用过渡的角色增加双倍采样成本。共享片段不保存播放状态，姿态缓冲属于模型实例；每次 update 最多应用一次最终姿态和一次蒙皮。

动画由业务逐帧更新；绘制主通道、阴影和多个视口都不能再次推进时间。

### 播放事件

本轮提供类型化播放事件：片段开始、循环、完成、过渡完成。事件包含片段名、播放时间，循环事件还包含本次跨越的循环次数。

事件在本次最终姿态应用后统一派发。大 dt 跨多个循环时合并循环次数，完成事件每次播放仅派发一次；过渡中已被替换的源片段不派发完成或循环事件。回调中的播放切换推迟到本轮事件派发完成后执行，避免遍历期间重入修改状态。零时长片段应定义为一次完成，不产生无限循环。

首版不加入时间轴标记、根运动、加法混合、分层混合、重定向或可视化动画状态机。待机与行走的业务选择先在示例中实现。

### 模型节点与挂点

本轮增加稳定查询接口：

```haxe
// 已加入代码，用户已反馈示例测试通过。
model.getNodeByIndex(index);   // GLB 节点索引；非当前场景节点返回 null。
model.findNodes("Hand.R");   // 返回全部同名节点，允许重名。
model.createSocket(nodeIndex, "weapon"); // 返回挂在目标节点下的普通 Node3D。
```

挂点是普通 Node3D，保存道具相对骨骼的偏移，不复制骨骼矩阵或引入后端特殊绘制。动画继续拥有导入节点的局部姿态；业务通过模型外层节点移动整个角色，通过 socket 调整道具，避免与动画写入同一节点。

返回的导入节点是借用引用；首版不支持重排、销毁导入骨架节点。模型销毁沿节点树销毁 socket 及附件；需要保留附件时，调用方应先将附件移出。挂点创建时校验索引、活动场景和对象有效性。

验收：Idle/Walk 平滑互切；快速连续切换不跳回初始姿态；暂停、定位和停止符合契约；不同实例互不影响；道具跟随骨骼，模型平移、旋转和缩放只应用一次；新增功能不改变材质兼容时的多纹理合批规则。

## 里程碑二：相机与三维交互

### 相机控制

本轮在 `hx.controls3d` 提供 `OrbitCameraController3D` 与 `FollowCameraController3D`。控制器接收旋转、缩放、目标位置等指令并提供 `update(dt)`，不直接注册全局输入或创建帧循环。

环绕控制包含目标点、距离与俯仰范围；跟随控制包含目标节点、目标偏移与平滑参数。平滑按 dt 计算，暂停与恢复时由调用方决定是否直接对齐。第一版保持透视相机，不同时扩展正交投影与镜头碰撞。

输入适配绑定具体 Scene3D：已有二维事件命中视口后才开始操作；UI 消费的按下事件不启动相机拖动。拖动开始后记录 pointerId 并保持到抬起或取消，退出场景时解除监听。

### 查询与选择

本轮将 Scene3D.pick 内部几何求交抽成可复用的 Raycaster3D，pick 保留舞台坐标入口与现有返回语义。新增射线查询的最大距离、对象过滤和网格到所属 Model3D 的查询；明确普通世界射线与视口拾取的近远裁剪差异。Scene3DInput 提供事件路由适配，独立验证入口为 samples/camera-interaction，尚未编译或运行。

原始射线查询只负责几何，不自动检查二维 UI、材质 Alpha 或遮罩。交互适配利用现有二维事件路由和 Scene3D.pick，先提供选择回调，不立即建立第二套完整事件冒泡系统。

示例用水平地面射线求交确定移动目标，以简单运动学位移驱动角色。该能力不承诺重力、碰撞响应或导航避障。

验收：缩放或变换后的二维视口仍正确拾取；动画网格与挂点附件可选；两个视口互不串输入；UI 按钮不触发场景移动；拖动出界后释放不会留下持续旋转状态。

## 里程碑三：可操作的角色场景

新增 `samples/interactive-character`，复用现有可生成的带贴图机器人资源，通过 Assets 加载，提供以下完整流程：

1. Procedure 进入场景并加载资源，显示加载状态与错误重试入口。
2. 生成地面与多个角色，点击选择角色或指定地面目标。
3. 角色移动时切换 Walk，到达后过渡回 Idle；可调整速度与切换受控角色。
4. 手部挂载道具，相机跟随、环绕与缩放；二维 UI 显示当前动作与性能统计。
5. 退出时销毁输入适配、控制器和模型，再清理 Assets；支持重复进入。

示例统一拥有更新顺序：业务状态与位移 → 动画及蒙皮 → 跟随相机 → 绘制。控制器、动画都只推进一次，Scene3D 渲染器消费结果。窗口多次绘制或上下文恢复不增加动画时间推进次数。

首版场景配置使用 Haxe 代码；待对象、挂点和所有权稳定后，再决定是否增加版本化 JSON 场景资源。避免现在冻结尚在变化的序列化格式。

## 多纹理与性能策略

动画过渡、挂点和相机控制只改变最终几何与变换，不必增加每角色 shader uniform，原有多纹理合批可继续使用。不同程序、公共 uniform、混合、深度或采样状态依然会分批，不能承诺所有角色与道具始终只有一次 DrawCall。

继续保留 CPU 蒙皮兼容路径。GPU 蒙皮需要共同设计骨骼数据寻址、实例标识、设备限制与阴影通道；简单地为每个角色绑定不同骨骼 uniform 会影响跨角色合批，不能直接视为现方案的无成本替换。

本阶段记录动画求值、蒙皮、查询、相机和完整渲染 CPU 耗时，继续观察上传量与分批原因。先以现有基线控制回归；后续若项目表现出瓶颈，再评估姿态缓冲复用、静态缓冲保留或 GPU 蒙皮。保持静态场景 `autoRender=false` 的按需重绘行为。

## 实施顺序与完成条件

| 顺序 | 交付内容 | 完成条件 |
| --- | --- | --- |
| 1A | 实例姿态求值拆分与动画过渡 | 旧播放接口保持兼容，连续过渡及实例隔离正确 |
| 1B | 节点查询、挂点、播放事件 | 附件跟随及销毁正确，事件无重复或重入混乱 |
| 2A | 环绕与跟随控制器 | 独立 dt 更新，可显式接入和释放 |
| 2B | 射线查询与交互适配 | 几何选择、视口坐标与 UI 输入边界明确 |
| 3 | 完整角色交互示例与报告 | 用户确认可操作、重复进出与恢复正常，基线无未解释退化 |

每个里程碑完成后先通知用户，由用户测试；本设计阶段不运行编译、示例或性能测试。后续验收覆盖原有二维混合、阴影、多视口、多纹理开关、上下文恢复和资源生命周期；比较性能时固定设备、浏览器、构建与场景参数，不以改变帧调度获得收益。

PBR、多光源、软阴影、物理、导航、场景编辑器、GPU 实例化和完整 glTF 扩展支持不列入本阶段完成条件。之后按实际项目的画质、规模和交互需求分别立项。
