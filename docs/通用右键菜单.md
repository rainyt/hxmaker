# 通用右键菜单

`ContextMenu`、`ContextMenuItem`、`ContextMenuSeparator` 和 `ContextMenuContext` 均位于 `hx.display` 包。菜单继承 `Box`，接受任意显示对象作为条目，默认使用纵向布局、2 像素间距和 4 像素内边距。可替换 `layout`、`background`，或继承标准条目并覆盖 `updateStyle()` 定制外观。

```haxe
var menu = new ContextMenu();
menu.addItem(new ContextMenuItem("重命名", context -> {
    // 业务逻辑自行实现，捕获本次的数据。
    rename(context.owner);
}));
menu.addItem(new ContextMenuSeparator());
menu.addItem(new CustomDisplay());
display.contextMenu = menu;
```

绑定不会修改 `mouseEnabled`、`mouseChildren` 或选择策略。普通 `Box` 的空白命中需自行设置尺寸和 `mouseClickEnabled = true`；Tree、FinderView、ListView 的滚动视口已有有效命中范围。默认 `contextMenu` 为 `null`，只有非空绑定才注册菜单专用监听；重复赋同一菜单不改变当前展示。

## 上下文与事件

`context.owner` 是绑定对象，`context.target` 是原始命中对象，`stageX/stageY` 是该舞台坐标。菜单以 `MouseEvent.RIGHT_CLICK` 触发，舞台先分发整个鼠标事件路径，再打开最近绑定的菜单。因此 Tree、FinderView、ListView 的正常右键选择先于菜单生成，与菜单绑定和监听注册顺序无关。菜单处理不调用鼠标事件的 `preventDefault()`，保持原有控件监听行为。

事件顺序为 `OPENING → OPENED → CLOSED`，每个事件的 `data` 都携带本次上下文。`OPENING` 前可读取 `menu.context`；可在监听中修改内容、禁用条目或调用 `preventDefault()` 取消。取消或最终为空时只有 `OPENING`，不回退到父级菜单，属性上下文随即清空。关闭后 `context == null`，`CLOSED.data` 仍为关闭前上下文。`close()` 幂等。

```haxe
var menu = new ContextMenu();
menu.addEventListener(ContextMenu.OPENING, (event:Event) -> {
    var context:ContextMenuContext = cast event.data;
    var item = tree.getItemByRenderer(context.target);
    menu.clearItems();
    if (item == null) {
        menu.addItem(new ContextMenuItem("创建根对象", _ -> createRoot()));
    } else {
        var data = item.data;
        menu.addItem(new ContextMenuItem("重命名", _ -> rename(data)));
    }
});
tree.contextMenu = menu;
```

FinderView 同样提供 `getItemByRenderer(target)`；ListView 新增 `getItemByRenderer(target):Dynamic` 和 `getItemIndexByRenderer(target):Int`，空白、回收对象或尚未完成刷新的渲染器分别返回 `null`、`-1`。不要使用 `selectedItem` 冒充实际右键对象。右键已选中节点保留 Tree/FinderView 的多选集合；`rightClickSelectEnabled = false` 仅禁止改变选择。Tree 箭头的右键不展开，FinderView 文件夹的右键不导航。

标准项默认 `enabled = true`、`closeOnSelect = true`。禁用项不执行也不关闭；分隔线不执行且不关闭。标准项回调拿到本次上下文的独立快照；回调内重新打开菜单时，旧操作不会关闭新展示。异步操作仍应在回调时捕获业务数据，避免依赖后来回收的行渲染器。自定义条目不自动关闭，可以持续输入或拖动，需要关闭时主动调用 `menu.close()`。

## 展示、焦点和生命周期

菜单由绑定对象实际所属的 Stage 承载，不依赖 `Hxmaker.topView`，不受原控件的遮罩或布局影响。每个舞台最多展示一个菜单，`stage.openedContextMenu` 可读取当前展示，`stage.contextMenu` 则是舞台自身的绑定；浮层排在该舞台内部顶部，跨舞台顺序遵守引擎的舞台叠放和命中规则，不穿透上层模态舞台。当前核心没有单独的窗口模态管理器。

测量后根据舞台边界避让。内容过大时限制滚动视口尺寸；滚轮纵向滚动，Shift+滚轮横向滚动，只有横向超出时也可直接滚轮横向滚动。自定义控件的拖动不会拖动整个菜单。改变舞台尺寸会重新限制和避让。

菜单外左键或右键按下、Esc、舞台失活、owner 移出舞台或解绑时关闭。外部点击检测在冒泡前完成，内部显示对象都能正常接收鼠标输入。Esc 在焦点输入框处理前关闭菜单，其余按键按原焦点机制处理。保留 Stage 的静态共享焦点；菜单不主动抢焦点。内部控件获得焦点后，关闭时仅当焦点仍属于菜单浮层才恢复仍在有效舞台上的旧焦点，旧焦点失效时置空，不覆盖其他控件或舞台后来获得的焦点。

```haxe
// 解除引用，不销毁共享菜单。
display.contextMenu = null;
// 关闭并移除显示关系，条目仍可复用。
menu.close();
menu.clearItems();
// 关闭、解除所有绑定，销毁仍属于菜单的条目。
menu.dispose();
```

绑定对象销毁会解绑，但不销毁菜单；对象移出舞台关闭自己的展示，重加舞台后绑定继续有效。其他对象解绑不会关闭当前 owner 打开的共享菜单。菜单销毁后不能再次绑定或打开。`clearItems()` 不销毁条目，动态重建时使用方需管理移出的条目；示例对自己创建的临时条目主动调用 `dispose()`。菜单关闭会清理全部临时舞台输入监听和历史上下文。

## 后端与验证

hxmaker 核心不依赖 DOM、OpenFL 或 Electron。hxmaker-openfl 复用已有右键抬起生成 `RIGHT_CLICK` 的路径；HTML5 原生 `contextmenu` 仅查询接管状态，不再次派发右键事件。绑定菜单取消打开或为空也视为接管；未绑定区域保留既有行为。浏览器坐标经 CSS 显示尺寸、Lime 高清比例、OpenFL 显示变换转换为 hxmaker 坐标，兼容 Electron 的 HTML5 后端。

交互示例位于 `samples/context-menu/`：

```bash
cd samples/context-menu
haxelib run openfl test project.xml html5
```

在仓库根目录编译并执行行为验证：

```bash
haxe vscode-openfl.hxml
haxe test/context-menu-example.hxml
haxe test/context-menu.hxml
node -r ./test/context-menu-preload.js ./bin/context-menu-check.js
```

行为验证使用真实显示树、命中和舞台事件分发，覆盖绑定、事件顺序、取消、共享、父子优先、标准项、滚动、关闭清理与控件命中。Node 提供 OpenFL 静态初始化所需的最小画布环境，并固定文字测量，不启动 GPU；视觉效果、系统原生菜单及真实设备缩放仍需运行 HTML5 示例检查。
