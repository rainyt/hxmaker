# 3D 特效第一阶段使用说明

本阶段补充 CPU 粒子、广告牌、加法混合、生命周期曲线、序列帧和组合粒子播放器。第一阶段已由用户反馈测试通过。后续第二阶段的拖尾与动态材质扩展尚未进行编译和运行验收，见 [第二阶段使用说明](3D特效第二阶段使用说明.md)。

## 修改范围

核心库新增：

- `hx.display3d.Billboard3D`：面向相机的四边形，支持锁定世界 Y 轴、面内旋转和手动选帧。
- `hx.display3d.ParticleSystem3D`：单发射器集中生成动态网格，支持内部深度排序和粒子状态复用。
- `hx.display3d.Effect3D`：带延迟的多发射器播放、暂停、速度控制、自然收尾及完成事件。
- `hx.effect3d.ParticleSettings3D`：发射配置。
- `hx.effect3d.FloatCurve3D`：归一化寿命上的分段线性曲线。
- `hx.effect3d.SpriteSheet3D`：等尺寸序列帧图集。
- `hx.material.EffectMaterial3D` 与 `BlendMode3D`：普通透明或加法混合的无光照材质。

现有 `Geometry3D` 增加可选顶点 RGBA 数组 `colors`，四个浮点数对应一个顶点；空数组沿用全白。直接修改数组后调用 `invalidate()`。`Material3D.blendMode` 默认 `NORMAL`，仅在 `alphaMode = BLEND` 时生效。`MeshObject.renderOrder` 默认零，仅控制透明通道，数值较大时后绘制。

必须同时更新相邻 `hxmaker-openfl` 库中的 `MeshBatch3D.hx` 和 `Renderer3D.hx`。后端读取逐顶点颜色，将混合模式纳入批次兼容判断，支持透明优先级，并保留离屏目标中 alpha 为零的发光 RGB。旧后端不会应用这些新增渲染语义。

## 示例启动规范

项目入口统一继承 `hx.core.HxmakerApplication`，构造函数中调用 `super()`，再通过 `init(Game, 960, 640)` 初始化业务舞台。业务舞台 `Game` 继承 `hx.display.Stage`，在 `onStageInit()` 中先调用 `super.onStageInit()`，再创建三维场景和界面。启动类不重复初始化引擎，特效更新逻辑放在业务舞台或场景中。

三维特效示例已拆分为 `samples/effects-3d/Source/Main.hx`（应用入口）和 `samples/effects-3d/Source/Game.hx`（业务舞台）。

## 最小粒子用法

```haxe
import hx.display3d.ParticleSystem3D;
import hx.effect3d.FloatCurve3D;
import hx.effect3d.ParticleSettings3D;
import hx.material.BlendMode3D;
import hx.material.EffectMaterial3D;

// texture 是由资产系统持有的 hx.display.BitmapData。
var material = new EffectMaterial3D(texture, BlendMode3D.ADD, 0xffbb55);
var config = new ParticleSettings3D();
config.emissionRate = 40;
config.duration = 1;
config.burst = 16;
config.coneAngle = 35;
config.gravity.setTo(0, -2, 0);
config.size = new FloatCurve3D([0., 0.2, 1.], [0., 1., 0.]);
config.alpha = new FloatCurve3D([0., 0.8, 1.], [1., 1., 0.]);

var particles = new ParticleSystem3D(material, config);
scene.root.addChild(particles);
particles.setPosition(0, 1, 0);
particles.play();

// 在业务更新循环中调用，dt 使用秒；每帧只推进一次。
particles.update(dt, scene.camera);
```

这些三维节点不自动订阅舞台更新。先更新动画和骨骼挂点、发射器位置及相机，再调用粒子或组合播放器的 `update`。挂入骨骼节点的方法沿用模型现有的挂点接口。

## 发射与模拟

- `play()` 清除旧粒子并重置时钟，立即发射 `burst` 数量；首次绘制仍需 `update`。
- `duration > 0` 时，到期只停止持续发射，等待存活粒子消失；`duration = 0` 表示持续发射。
- `emit(count)` 额外爆发，不开启持续发射；独立爆发也可在停止状态调用。
- `stop()` 停止发射，之后继续调用 `update` 直到自然结束。`stop(true)` 立即清空。
- `paused = true` 冻结模拟，但调用 `update` 时仍根据相机重建广告牌。
- `Event.COMPLETE` 在每次播放或独立爆发自然结束时派发；立即停止一个活动系统也会完成。空发射器在下一次更新判断结束。
- `worldSpace` 在 `play()` 或停止状态的首次 `emit()` 时锁定，播放中修改配置不会改变存活粒子的空间。
- 世界空间模式下，出生位置和初速度通过发射器世界矩阵变换，之后不再跟随发射器；重力使用世界坐标。
- 局部空间模式下，位置、速度、重力在发射器局部坐标中模拟，粒子中心跟随父节点变换。
- `radius` 为球形发射区域的局部半径；零表示点。方向绕局部 +Y 分布，`coneAngle = 180` 覆盖整球方向。
- 广告牌宽高和粒子绘制尺寸使用世界单位，不随父节点缩放变化；父节点缩放仍会影响局部空间粒子中心及世界空间出生速度。需要整体放大效果时，同时调整尺寸曲线／尺寸范围、速度和发射半径。

`maxParticles` 限制为 1 至 16383，保持单网格顶点数量在 16 位索引范围内。超额发射直接丢弃；很大的时间步仅处理最近的有限次发射，不补齐已经结束的历史粒子。状态使用对象池，网格与排序仍由 CPU 每帧更新。

## 颜色、序列帧与广告牌

`size`、`alpha`、`red`、`green`、`blue` 的输入是粒子归一化寿命。尺寸曲线乘出生时随机尺寸；颜色和透明度曲线限制到零至一，再乘材质颜色与透明度。曲线时间必须在零至一之间严格递增，区间外取端点值。

```haxe
config.sheet = new hx.effect3d.SpriteSheet3D(4, 4, 12);
```

图集每格大小相同，按从左到右、从上到下顺序播放前 12 帧，随寿命播放一次；UV 相对于材质引用的贴图区域。图集需要自行留出透明边缘，避免线性采样串色。

```haxe
var sprite = new hx.display3d.Billboard3D(material);
scene.root.addChild(sprite);
sprite.billboardWidth = 2;
sprite.billboardHeight = 2;
sprite.lockY = true;
sprite.sheet = new hx.effect3d.SpriteSheet3D(4, 4);
sprite.frame = 5;
sprite.update(scene.camera);
```

广告牌默认按相机坐标轴对齐；锁 Y 模式保持世界竖直。尺寸零或不可逆父变换不会提交可见四边形。广告牌材质请使用 `EffectMaterial3D`，或自行设置透明阶段与双面剔除状态。

## 组合播放器

```haxe
var effect = new hx.display3d.Effect3D();
scene.root.addChild(effect);
effect.addEmitter(smoke, 0);
effect.addEmitter(explosion, 0.5);
effect.play();

// 组合播放器负责推进其轨道，不再单独 update(smoke/explosion)。
effect.update(dt, scene.camera);
```

只在停止状态调用 `addEmitter`，同一发射器只能加入一次，且必须保持为该播放器的直接子节点。`play()` 重置所有轨道。`speed` 为非负时间倍率，`paused` 冻结整个时间轴。播放器从跨越延迟点的剩余时间开始推进轨道，而非直接推进完整帧。

`stop()` 取消尚未启动的轨道，让已经启动的粒子收尾；`stop(true)` 立即清空并完成。`loop = true` 在全部轨道自然收尾后重新播放，循环长度包含粒子尾部；它不按固定时长重叠启动新一轮。包含持续发射轨道的组合不会自动完成，需要主动停止。完成事件使用 `Event.COMPLETE`。

播放器拥有轨道节点，销毁播放器会销毁这些节点；发射器和广告牌只释放自己创建的几何，不销毁调用者的共享材质和贴图。共享资源应在全部使用者释放后由资产所有者销毁。

## 后端与性能边界

普通透明混合使用预乘颜色。加法模式累加已经乘透明度的 RGB，同时保留目标 alpha，让光效叠加到透明三维视口后的二维背景。合成路径保留超过 alpha 覆盖率的发光分量，并应用视口透明度及颜色倍率。当前颜色目标仍为普通范围，不提供 HDR 或 Bloom。

不透明物体先绘制；透明网格先按 `renderOrder` 升序，再按包围盒中心从远到近排序。发射器内部的粒子也从远到近排序。不同发射器相互穿插时，粒子不会跨发射器全局排序；可考虑合并发射器或显式设置层次。

一个发射器使用一个网格，并不保证一个独立 DrawCall。兼容网格可能合批，纹理槽位、索引上限、材质和混合状态会导致拆批。观察 `scene.stats.drawCalls`、`uploadedBytes` 与透明区域层叠数量。第一阶段没有增加实例化或 GPU 模拟。拖尾、UV 滚动和溶解已在第二阶段补充；软粒子和后处理仍未实现。

## 示例与待执行验收

示例位于 `samples/effects-3d`，程序生成贴图，不依赖外部素材，展示火球拖烟、延迟命中爆炸、四帧动画和地面光圈，点击标题暂停；左键或单指拖动环绕镜头，滚轮缩放，暂停时仍可操作镜头。轻点视口切换背景透明度，拖动不会触发背景切换。

在获得测试授权后，建议执行：

1. 编译 `samples/effects-3d` 的 HTML5 版本，检查新接口与后端编译。
2. 在浏览器中观察粒子、四帧爆炸、深度遮挡、普通透明和加法混合；切换透明场景背景检查发光合成。
3. 检查暂停时相机转动、延迟轨道、重播、自然停止、立即停止和完成事件次数。
4. 检查局部／世界空间、骨骼挂点、非均匀缩放父节点、零缩放、粒子容量与大时间步。
5. 编译并运行已有基础三维示例，检查原有光照、透明、二维合成、按需重绘及 GL 状态恢复没有回归。
