# 基础 3D 框架实现方案

日期：2026-10-16。状态：首版代码已通过 HTML5 示例编译和基础浏览器验证，完整验收尚未完成，范围见《基础 3D 框架验证记录》。本文保留设计目标，实际 API 和限制见《基础 3D 框架使用说明》；部分后端职责合并在 Renderer3D 中实现。

## 1. 目标与总体决定

在现有 hxmaker 上增加一个基础 3D 子系统，保留现有 2D UI 和多纹理合批能力。3D 采用同样的多纹理原理：一个批次绑定多张纹理，顶点携带纹理编号，片元着色器按编号采样。

确定以下实现方向：

1. `hx.display.Scene3D` 继承 `DisplayObject`，可以加入现有显示树。
2. `hx.display3d.Node3D` 维护独立三维对象树；`MeshObject` 和 `Camera3D` 继承它，不继承 `DisplayObject`。
3. `MeshObject` 通过 `Geometry3D` 和 `Material3D` 描述几何与外观，不直接持有 OpenFL 类型。
4. 3D 场景先绘制到独立颜色纹理和深度缓冲，再按 `Scene3D` 的二维位置与显示顺序合成。
5. 首版使用 CPU 合并世界坐标顶点，加 GPU 相机投影，实现不同模型、不同纹理的批量绘制。
6. 首个后端为 OpenFL 的 OpenGL/WebGL 路径。Canvas、Cairo、DOM 等路径首版不提供 3D 绘制。
7. 首版直接在现有 `hxmaker-openfl` 中增加后端模块，不先拆第三个库；核心接口不绑定它，后续可以提取。

这是一套基础场景与渲染框架，不以首版覆盖完整商业 3D 引擎为目标。

## 4. 对象关系与使用方式

```text
Stage
├── Image：背景
├── Scene3D：二维视口
│   ├── root：Node3D
│   │   ├── Camera3D
│   │   ├── MeshObject：地面
│   │   └── Node3D：角色根节点
│   │       ├── MeshObject：身体
│   │       └── MeshObject：武器
│   └── camera：当前活动相机的引用
└── Sprite：二维 UI
    ├── Label
    └── Button
```

`Scene3D` 不是 `DisplayObjectContainer`，不接收二维 `addChild()`。三维对象通过 `scene.root.addChild()` 加入，可在多个 Node3D 层级中组合，最终归属于一个 Scene3D。

以下仅表示拟定 API，不是当前可运行代码：

```haxe
var scene = new Scene3D(640, 360);
scene.x = 40;
scene.y = 60;
stage.addChild(scene);

var camera = new Camera3D();
camera.setPosition(0, 2, 6);
camera.lookAt(new Vector3D(0, 0, 0));
scene.root.addChild(camera);
scene.camera = camera;

var material = new UnlitTextureMaterial();
material.texture = assets.getBitmapData("crate");

var mesh = new MeshObject(BoxGeometry.create(1, 1, 1), material);
scene.root.addChild(mesh);

scene.addEventListener(Event.UPDATE, function(_) {
    mesh.rotationY += Hxmaker.engine.dt * 45;
});

var hit = scene.pick(stageX, stageY);
if (hit != null) {
    trace(hit.object.name);
}
```

二维 UI 可以盖在 Scene3D 上方；不同 Scene3D 之间按显示列表顺序合成，不共享三维深度，也不会相互穿插遮挡。

| `hx.geom.Bounds3D` / `Ray3D` | 空间包围盒与射线运算 |
| `hx.events.PickResult3D` | 命中对象、世界命中点、距离、三角形编号与 UV |
| `hx.render3d.IScene3DRenderer` | 可选的 Scene3D 绘制接入接口 |
| `hx.render3d.Scene3DStats` | 批次数、三角形数、纹理槽位占用、上传字节数与分批原因 |

`Node3D` 可继承现有 `EventDispatcher` 复用监听能力；其 parent 是 Node3D，不能混用 DisplayObject 的 parent。

节点提供 `addChild()`、`removeChild()`、`remove()` 和只读 children 访问；禁止把自己或祖先加入子树。重新挂接节点时递归更新场景归属与失效通知。活动相机必须属于当前场景；移除活动相机后暂停该场景绘制并提示缺少相机。

`Geometry3D` 的数组由修改方法维护版本；若提供可写数组，调用者修改后必须显式调用 `invalidate()`。节点变换采用标量属性或 `setPosition()` 等方法，避免修改可变 Vector3D 后无法检测变化。

首版只使用现有 Matrix3D 的明确数学运算，不依赖 DisplayObject 上的试验性 `matrix3D` 属性。矩阵乘法顺序和上传布局在实施时通过已知变换用例确认。

## 6. 坐标、视口与场景属性约定

### 6.1 三维坐标

- 采用右手坐标系：X 向右，Y 向上，相机默认朝局部 -Z。
- 位置单位为世界单位，与屏幕像素无固定比例。
- 对外旋转属性用角度，内部构造矩阵时转换；约定 `Mlocal = T × Rz × Ry × Rx × S`。
- 数学表达采用列向量：`Mworld = Mparent × Mlocal`，`V = inverse(McameraWorld)`，`clip = P × V × Mworld × localPosition`。
- GPU 做完整齐次投影和透视除法，不在 CPU 上将模型投影成二维三角形。
- 非法相机参数、奇异相机矩阵需要明确报错；零缩放节点可跳过绘制与拾取。负缩放按世界矩阵行列式调整绕序，并将有效绕序纳入批次键。

透视相机默认垂直视场角为 60 度、near=0.1、far=1000；要求 `0 < near < far`、有效视口宽高比，以及介于 0 和 180 度之间的视场角。`lookAt()` 以世界坐标为输入，需考虑相机父节点变换；目标重合或上方向退化时明确拒绝更新。

这些是新 3D 子系统的约定，实施时需用适配方法匹配现有 Matrix3D 的 append/prepend 行为，不根据方法名猜测顺序。

### 6.2 Scene3D 视口

- `new Scene3D(width, height)` 的尺寸表示未应用二维缩放的逻辑视口尺寸。
- 重写 width/height 的相关访问逻辑，设置尺寸用于改变视口；`scaleX/scaleY` 只控制最终二维合成缩放。
- 首版建议 width/height 返回逻辑视口尺寸；这是 Scene3D 的明确约定，与基类默认的缩放后宽高行为不同。布局兼容在实施阶段处理。
- `renderScale` 默认 1；物理目标尺寸按逻辑尺寸、设备像素比与 renderScale 计算，并受纹理/渲染缓冲上限约束。
- 二维缩放默认不自动放大离屏目标，避免父容器动画触发逐帧分配；需要更清晰画面时调整 renderScale。
- 尺寸为零时停止绘制；相机宽高比默认跟随视口。
- `Scene3D.alpha`、二维变换与父级颜色变换在最终合成时应用一次，不重复乘入三维材质。
- Scene3D 继承的 `shader` 只表示二维合成阶段效果；模型的 3D Shader 通过 material 设置。首版默认合成程序，不承诺任意现有 GraphicsShader 可直接用于自定义合成。
- 默认背景透明，离屏清理颜色为 `(0,0,0,0)`，深度每次重绘重置。

## 7. 多纹理合批算法

### 7.1 与现有多纹理原理的对应

| 现有 2D 路径 | 新 3D 路径 |
| --- | --- |
| 二维位置顶点 | 世界空间三维位置顶点 |
| 顶点纹理编号 | 顶点纹理编号 |
| 批次贴图表 | 批次贴图及采样配置表 |
| 多个 sampler2D 与条件分支 | 多个 sampler2D 与按槽位生成的条件分支 |
| 二维显示矩阵 | 共享的相机 ViewProjection 矩阵 |
| 图片四边形拼接 | 任意索引三角网格拼接 |

不直接继承现有 `MultiTextureShader`，它包含二维颜色变换、OpenFL GraphicsShader 属性与图片路径假设。新着色器复用其设计原理，避免要求旧 2D 顶点格式承载新功能。

### 7.2 首版顶点格式

```text
position.xyz       3 个 Float，世界坐标
uv.xy              2 个 Float，归一化后的纹理坐标
textureId          1 个 Float，当前批次内的纹理槽位编号
color.rgba         4 个 Float，模型颜色与有效透明度
```

共 10 个 Float，即 40 字节；对应 4 个顶点属性。首版无光照，无需为每个顶点上传法线；后续增加有光照变体时再增加法线属性和逆转置矩阵处理。

每个三角形的三个顶点必须使用相同 textureId。如果不同材质的三角形共享顶点，需要在材质边界拆分顶点或分别提交。首版一个 MeshObject 对应一份几何和一个材质。

### 7.3 为什么首版在 CPU 上合并世界坐标

如果逐模型通过 uniform 修改 ModelMatrix，每次修改就无法继续用同一个共享 uniform 批量绘制。首版先把模型顶点变换到世界空间，再合并到批次：

```text
模型本地顶点 → CPU 世界变换 → 批次顶点缓冲
批次顶点缓冲 → GPU ViewProjection → 深度测试与片元采样
```

这样一个批次只需要一份 ViewProjection，可以包含不同位置、不同几何、不同贴图的网格。

缓存按几何版本与世界矩阵版本保存世界顶点。相机移动只更新可见性、排序和 ViewProjection，不必重新计算世界顶点；但可见集合或批次成员变化仍可能导致重新打包与上传。

此方案适合基础框架与中小场景，大量动态高面数模型会消耗 CPU 与上传带宽。后续通过静态批次、每模型缓存缓冲和 GPU 实例化优化；不承诺首版支持大规模动态场景。

### 7.4 批次兼容键

以下条件必须兼容，才能进入同一批次：

- 当前 Scene3D、活动相机、目标与渲染阶段。
- Shader 程序及变体、顶点格式和拓扑类型。
- 未编码进顶点的全部材质参数，包括自定义 uniform。
- 深度测试与写入、混合模式、剔除方式和有效绕序。
- 采样模式及纹理数据约定；首版可将过滤/环绕配置作为批次公共状态。
- 当前批次允许的槽位数、顶点数、索引数与缓冲字节预算。

纹理资源身份本身不作为必须相同的批次条件，由纹理槽位表解决。不同 Material3D 实例只要上述值相同，就可以合批；相同 Shader 配不同 uniform 则需要分批。

首版自定义 Shader 只有遵守标准顶点输入、ViewProjection、采样与输出协议，才参与自动合批；其他材质走独立提交，仍使用同一个场景渲染流程。

### 7.5 纹理表、容量与提交

1. 对排序后的绘制项，先比较批次兼容键。
2. 查询底层 GPU 纹理是否已经存在于当前槽位表；图集不同区域共享底层纹理。
3. 如果新增纹理会超限，或几何容量超限，提交当前批次，再在新批次重新分配槽位。
4. 将模型顶点复制到批次，写入世界位置、实际 UV、textureId 与颜色。
5. 索引加上当前顶点偏移；提交时一次绑定批次的全部纹理并绘制。
6. 遍历结束提交剩余批次。

默认使用 16 位索引。首版单批次最多 65,535 个顶点，保守避开最大索引的特殊情况；单个超大网格按三角形拆分并重映射顶点，不截断、不产生越界索引。

图集纹理需要将局部 UV 映射到 rect 所指的实际区域；首版拒绝带旋转或裁边还原语义的图集帧，除非资源适配层已明确转换。无纹理材质使用共享白色纹理，也占一个实际槽位。

首版默认纹理使用 CLAMP_TO_EDGE、无 mipmap，提供 LINEAR/NEAREST 过滤。WebGL 1 路径对非二次幂纹理的重复和 mipmap 请求做能力检查与明确处理，不生成不完整纹理。不能在同批次中以互相冲突的采样配置使用同一个底层纹理对象。

纹理槽位只在批次内部有效，不能永久写回 Geometry3D。批次缓存发生重新分组时必须重建编号与纹理表。

### 7.6 着色器与能力回退

默认顶点程序的核心计算：

```glsl
gl_Position = uViewProjection * vec4(aPosition, 1.0);
vUV = aUV;
vTextureId = aTextureId;
vColor = aColor;
```

片元采样延续现有的多个独立 sampler 与静态分支方式，例如：

```glsl
if (vTextureId < 0.5) {
    color = texture2D(uSampler0, vUV);
} else {
    color = texture2D(uSampler1, vUV);
}
```

必须根据实际槽位数 N 同时生成恰好 N 个 sampler 声明和采样分支，不照搬现有固定 8/16 分支。查询片元纹理单元、合并纹理单元、顶点属性和目标尺寸限制，初始槽位上限设为 16；首版不在顶点阶段采样纹理。相关限制见 [WebGL 1.0 规范](https://registry.khronos.org/webgl/specs/latest/1.0/)。

后端在上下文有效后创建程序。如果所选 N 编译或链接失败，则降低槽位数并重试，最低为 1；保留失败日志。单纹理程序也失败时报告 3D 不可用，不显示伪造成功的空画面。

片元精度同样按设备能力选择，优先使用支持的高精度配置；不能把低端设备缺少片元 highp 的情况误判为纹理槽位不足。纹理上传若必须修改像素解包状态，也需要恢复对应状态。

`Renderer3D.multiTextureEnabled` 独立控制三维路径，关闭时 N=1；现有二维开关保留原含义。能力与程序缓存按上下文保存，不使用跨设备的全局可变槽位数。

## 8. 材质、透明与剔除

### 8.1 材质基本属性

```text

uniforms / version
```

首版先提供 OPAQUE 与 BLEND，MASK 在基础阶段末补齐。默认剔除背面；几何生成器使用一致的正面绕序。

纹理桥接必须标记来源纹理是直通 Alpha 还是预乘 Alpha，并在 Shader 中统一成预乘输出，避免把已预乘的 OpenFL 纹理再次乘 Alpha。最终合成也按预乘约定处理。

### 8.2 绘制队列

- OPAQUE：开启深度测试和深度写入，按批次兼容键组织，同组内可从近到远绘制。
- MASK：先做 Alpha 阈值丢弃，再进行与不透明物体相同的深度写入；阈值等公共参数参与批次键。
- BLEND：开启深度测试、关闭深度写入，按相机空间深度从远到近稳定排序，只合并排序后相邻且兼容的项。

首版透明排序以世界包围盒中心为依据，相交透明网格和单模型内部的交叉透明面可能排序不准确。这是明确限制，后续可通过拆分模型或更高级透明算法处理。

深度测试解决不同三角形的遮挡，不能用显示树顺序或简单 Z 排序替代。视锥剔除必须使用保守世界包围盒；无有效包围盒的对象暂不剔除。

## 9. 与 OpenFL 后端的接入

### 9.1 保持 IRender 兼容

新增一个独立可选接口，避免向现有 IRender 强制加入所有后端都必须实现的方法：

```haxe
interface IScene3DRenderer {
    public function renderScene3D(scene:Scene3D):Void;
}
```

OpenFL `Render` 实现该接口，持有自己的 Renderer3D。`renderDisplayObject()` 识别 Scene3D，并转发到新入口；其他类型继续走现有路径。对于缺少扩展能力的其他后端，在绘制 Scene3D 时提供明确的不支持提示。

这里的 `renderScene3D()` 负责准备或挂接 OpenFL 显示节点，不等同于立刻向 GPU 提交命令。

渲染队列中的批次持有稳定的缓冲范围、纹理表和 uniform 快照，不能引用下一个批次会覆写的临时数组。业务更新每帧执行一次，渲染回调不再修改模型或推进动画。

### 9.2 区分两种提交时机

现有 `endFillImageDataBuffer()` 会把批次转成 OpenFL 图形节点；实际 GPU 绘制在 OpenFL 后续遍历时发生。因此不能在 hxmaker 的二维遍历中随意执行原始 GL 绘制，并把它当作正确的最终显示顺序。

拟定接入流程：

1. hxmaker 遍历到 Scene3D，结束前面的二维图形批次。
2. 创建或复用属于该场景的 `Scene3DDisplay`，设置其二维世界变换、颜色和目标信息，插入当前正确的 OpenFL 容器。
3. 后续二维对象继续生成图形节点，形成正确的前后顺序。
4. OpenFL 实际绘制 Scene3DDisplay 时，在其 GPU 回调中按需更新离屏目标，并绘制目标纹理的合成四边形。

OpenFL 官方提供 `RenderEvent.RENDER_OPENGL`，其回调在对象实际绘制时发生；事件及 renderer 不能保存后延迟使用。此接口标为 Beta，需封装在后端适配器内并与实际安装版本对齐，见 [RenderEvent 文档](https://api.openfl.org/openfl/events/RenderEvent.html)。

当前上下文可通过回调中的 OpenGLRenderer 获取。该接口供自定义 OpenGL 绘制使用，见 [OpenGLRenderer 文档](https://api.openfl.org/openfl/display/OpenGLRenderer.html)。不另建一个与二维舞台无关的上下文，也不在业务更新回调中直接绘制。

### 9.3 离屏目标与合成

- 每个 Scene3D 拥有独立的 RGBA 颜色纹理和深度附件。
- 切入离屏目标后关闭或重设继承的 scissor/stencil，完整清理自己的目标；不能误用父容器的裁剪状态。
- 完成三维绘制后恢复进入回调时的 framebuffer、viewport 与父级裁剪，再合成四边形。
- 合成使用当前目标上下文中同一张 GPU 纹理，不通过逐帧 readPixels 或 CPU 位图拷贝传递画面。
- 优先由自定义合成程序直接采样目标纹理；如需包装为 OpenFL BitmapData，只在验证其纹理接入与生命周期可靠后使用，不能假设现有 IBitmapData 已支持任意外部纹理。
- 合成处理 RenderEvent 对象矩阵、父级透明度/颜色变换、UV 方向和预乘 Alpha，并尊重当前容器的 scissor/stencil。
- 首版正常合成模式为 NORMAL；额外混合和自定义二维 Shader 在确认适配后逐项开放。

离屏渲染至少增加一次最终四边形绘制。统计中分别记录三维批次与二维合成，不能将整个 Scene3D 记成恒定一次 DrawCall。

### 9.4 GPU 状态隔离

保存并恢复三维路径会修改的程序、framebuffer、viewport、活动纹理单元及其绑定、顶点/索引缓冲、顶点属性、深度、剔除、混合、颜色写入、scissor、stencil，以及使用时的 VAO 等状态。

尤其需要同时处理 OpenFL 的程序与 Context3D 状态缓存：仅恢复底层 GL 状态，不代表 OpenFL 缓存正确；仅修改缓存，也不代表 GPU 已经绑定正确。以实际安装版本的公开状态恢复能力为先，必要的私有适配集中到 RenderStateGuard3D，不散落在业务代码中。

本地 OpenFL 的 setShader() 已包含离屏绘制时的程序状态一致性检查。本次不修改 OpenFL 依赖源码，也不能假设这一项检查足以覆盖全部三维状态，因此仍需独立的状态恢复适配。

### 9.5 更新、缓存和生命周期

- Scene3D 默认 `updateEnabled=true`，在 `onUpdate(dt)` 中分发 UPDATE 并更新三维子系统。
- 默认 `autoRender=true`：场景可见并挂到舞台时每帧请求刷新，先保证动态场景正确；设为 false 时依赖版本失效和 `requestRender()`。
- Node3D、Geometry3D、Material3D、Camera3D 的变化均递增版本并通知使用它们的场景；共享材质与几何需要向所有使用场景通知。
- 内容未变化时重用离屏纹理；只有二维位置或透明度变化时只需重新合成。首版不为了避免少量遍历而牺牲正确性。
- 同一场景可能被离屏绘制多次；按帧号与内容版本避免重复更新业务逻辑，同时尊重每次合成的目标和变换。
- 后端 Render.clear() 会移除并重建显示节点，场景资源不能绑定临时对象池节点的归还生命周期。
- Scene3D 离开舞台时取消调度，销毁时释放它自己的目标、缓冲、引用和监听；共享几何、材质和资产纹理不随单个模型销毁而直接释放。
- 首版共享 Geometry3D、Material3D 由调用方显式管理生命周期；网格只持引用。资源仍被网格使用时禁止销毁，提供清晰错误；源 BitmapData 的所有权继续由 Assets 管理。
- 上下文丢失后暂停提交，丢弃 GPU 句柄；恢复后按上下文代次重建程序、纹理目标和缓冲。保留 CPU 几何与可重新加载的纹理来源。
- 渲染目标大小变化时重建尺寸相关资源，释放旧资源，避免累计显存。

### 9.6 首版兼容边界

正常舞台显示、多个场景、二维变换与透明度、矩形遮罩和滚动裁剪纳入验收。

`cacheAsBitmap`、BitmapData.draw、RenderFilter、场景截图等可能改变 OpenFL 的实际渲染路径。首版不能默认全部兼容：对非 OpenGL 回调给出清晰提示；对 GPU 离屏路径在第一阶段确认重入和目标恢复后再标记支持。既有二维对象的功能保持原有行为。

## 10. 拾取与事件

`scene.pick(stageX, stageY)` 的输入为 hxmaker 舞台坐标：

1. 使用 Scene3D 的二维世界逆矩阵转换到视口局部坐标，拒绝视口外坐标。
2. 转为标准化设备坐标，二维向下的 Y 转为三维屏幕向上的 Y。
3. 使用 ViewProjection 的逆矩阵反投影近、远点，并完成齐次除法，生成世界射线。
4. 先做世界 AABB 检测，再用节点逆世界矩阵将射线转到网格局部，检测三角形。
5. 将交点转回世界空间，以世界距离选择最近命中，避免非均匀缩放下使用局部距离比较。

首版按可见、可拾取几何做命中，不进行纹理 Alpha 像素检测。拾取结果包含对象、距离、世界坐标、三角形和 UV。

普通二维鼠标事件先命中 Scene3D 的矩形；调用者可在该事件中执行 pick()。自动尊重二维覆盖 UI 时，应通过正常舞台命中事件触发拾取；直接调用 pick() 只查询三维几何，不自动检查上方 UI 或所有祖先遮罩。

不直接依赖现有 globalToLocal() 完成精确拾取：当前实现需检查连续赋值时是否错误使用已修改坐标。可为拾取使用读取原始 X/Y 的独立二维逆变换；如修复通用方法，另行列明影响范围。

## 14. 本方案的实施结论

采用 Scene3D 视口加独立三维树的结构，在现有 OpenFL 后端中组合一个专用三维渲染器。多纹理能力沿用现有的纹理表、顶点编号与片元选图原理；几何提交、相机、深度与材质协议独立实现。

开始实施时优先完成 GPU 回调、离屏目标、状态恢复和 UI 合成，再实现网格与多纹理合批。这是首版能可靠接入现有体系的前提。
