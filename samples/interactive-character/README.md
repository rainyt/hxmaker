## 标准结构

```text
Source/Main.hx                        HxmakerApplication，只负责初始化
Source/Game.hx                        Stage，驱动独立流程管理器与常驻 UI
Source/app/GameContext.hx             流程请求、场景与加载会话所有权
Source/app/CharacterAssetSession.hx   Assets 加载、取消与迟到结果清理
Source/app/SampleConfig.hx            代码配置
Source/app/SampleAudit.hx             数值与文本诊断，不保留场景对象
Source/procedure/                     菜单、加载、游戏、错误四个流程
Source/game/CharacterScene.hx         Scene，三维世界与交互
Source/game/CharacterActor.hx         单角色移动、动作与道具业务
Source/ui/                           菜单、加载和错误界面
Assets/robot.glb                      Assets 统一加载的带贴图 GLB
```

业务不直接调用 OpenFL、Lime、浏览器、原生输入或底层渲染 API。后续输入修复在 Scene3DInput 中固定按下时的拾取结果，保留左键点击／拖动，不修改渲染接口或帧调度；该修复尚未编译或运行。

## 流程操作

1. 菜单选择 1 / 3 / 6 个角色，点击“进入角色场景”。
2. 加载界面显示 Assets 进度，可取消返回菜单。为方便检查取消，示例至少保留 0.6 秒加载界面；不是帧率限制。
3. 左键点击角色或道具切换选择，点击空白地面设置移动目标，自动过渡 Idle / Walk。抬起确认轻点后使用按下时固定的拾取结果，不受镜头继续平滑转动影响。
4. 左键拖动转镜头，滚轮缩放；拖动不会误下达移动指令。触摸同样为轻点选择／移动、单指拖动转镜头。可切换跟随／环绕、自动移动、暂停、速度、左右手挂点、道具显示、多纹理和阴影。
5. 底部“返回菜单”释放游戏场景与资源；“重新加载”重新走加载流程；“重建流程”销毁整个独立 ProcedureManager 再创建。

“暂停”冻结角色移动和动画，相机仍可操作。地面目标范围为 X/Z ±10，移动为示例运动学逻辑，没有碰撞、导航或重力。

菜单“演示加载失败与重试”会先正常加载和解码，再主动转入错误流程，便于重复检查资源交接与释放；它不伪装真实网络错误。错误页点击“重试正常加载”后重新创建会话。真实 Assets 加载或解码错误也进入错误流程。

## 生命周期循环与报告

“循环验收 ×5”由用户手动启动，执行五轮菜单 → 加载 → 游戏 → 菜单。每轮游戏至少停留一秒，且必须观测到一次实际三维渲染，再请求退出；返回菜单并完成释放后才累计完成数。最终停在菜单。错误流程会停止循环；“停止循环”停止后续自动切换，已经排队的切换仍会完成。

运行中底部显示活动流程、逻辑资源会话、在途加载、角色场景和循环计数。重建流程保留累计诊断，因此旧会话的迟到终态也能继续反映在计数中。

“输出诊断 JSON”通过标准 Haxe 日志输出一行：

```text
HXMAKER_INTERACTIVE_REPORT { ... }
```

遵守纯 hxmaker API 的要求，不用浏览器 API 下载文件或读写剪贴板。可从运行日志保存 JSON。报告包括：

- 流程创建／销毁次数，资源会话与在途请求计数。
- 世界更新次数、实际调用 Model3D.update 的次数。
- 每次退出的模型、输入适配和视口销毁标志，自建几何／材质的剩余引用及销毁状态。
- 最近至多 300 个观测到的新 renderId 的 CPU 耗时均值、P95，以及最近一次绘制批次、上传量和阶段耗时。
- 有界流程日志、真实错误及单独统计的演示故障数。

回到菜单并等待在途加载结束后，活动资源会话、在途请求和活动三维世界应为零；流程管理器仍为一个。正常退出记录应有模型／输入／视口已销毁、自建几何／材质引用为零、ownedResourcesDisposed=true。

这些是程序对象与引用诊断，不是 GPU 内存立即归零证明；Assets 底层缓存可继续保留。visualVerdict 保持“未自动判定”。CPU 样本跨场景、角色数及开关状态，属于观察窗口，不替代 [固定性能基线](../engine-acceptance/README.md)。

## 验收建议

- 正常进入，选择和移动角色，检查动画过渡、挂件、相机、阴影与多纹理切换。
- 左键拖动后释放，在镜头仍平滑转动时轻点地面，角色应前往按下时对应的目标；再次左键拖动仍可旋转镜头，且不应误下达移动指令。松开后普通鼠标移动不再旋转，二维 UI 不应触发移动。
- 暂停、改变速度和手部挂点，再恢复；确认移动与动画只由游戏流程推进一次。
- 加载中取消，再进入；迟到回调不能重新打开已取消场景。
- 执行一次演示失败，重试成功，再返回菜单。
- 运行五轮生命周期循环，在菜单输出诊断报告。
- 加载中和游戏中分别“重建流程”，确认输入、场景与资源计数回到预期。
- 如需上下文恢复复测，使用已有验收工具或浏览器自身的调试能力；本示例不新增原始 GL 调用。
