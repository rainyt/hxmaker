# 观测站性能优化记录

依据用户提供的 `Trace-20261019T064358.json.gz` 定位热点。CPU 采样总计约 5179 ms，其中 `getParameter` 自身约 2646 ms（51%），顶点整理约 452 ms（9%）。采样比例用于定位热点，不能直接等同于 FPS 提升比例。

## 改动

- OpenFL 后端按 WebGL 上下文跟踪状态写入，供三维状态保护读取。二维 OpenFL 和三维通道的状态修改均经过原始 GL 方法；缓存只避免重复查询，不省略恢复。纹理按槽位保存，VAO 切换使索引绑定重新求值，资源删除及上下文丢失/恢复使缓存失效。未跟踪的状态继续查询驱动。原生平台保持原路径，定义 `hxmaker_3d_full_state_queries` 可回到完整查询路径。
- 网格批次在一个网格内复用图集 UV 换算参数，直接写入顶点数组，减少逐顶点临时数组。
- 观测站关闭自动逐帧重绘；位置和朝向未变化时不重复提交相机矩阵。移动、跳跃、交互节点和雾设置的变化仍使三维缓存失效。
- FPS 统计文字默认每 0.25 秒刷新一次，底层统计仍逐帧采集；`refreshInterval = 0` 可恢复逐帧文字刷新。

保留模型、阴影、Bloom、距离雾和原有分辨率设置。

## 验证

- 真实 WebGL 状态对照：WebGL 2 共 173 项，WebGL 1 共 171 项，覆盖混合、深度、裁剪、纹理槽位、VAO、资源删除及读写帧缓冲绑定。
- 距离雾 12 项像素/功能回归，含上下文恢复；另在 WebGL 1 无 VAO 路径通过同样 12 项检查。
- 观测站行走、跳跃、闸门、任务、保存恢复和重进等 14 项回归通过，包括静止时重绘版本不递增的断言。
- 同一软件 WebGL 环境，预热后静止和行走的 `getParameter` 调用由每帧 33 次降为 0 次。首次进入、资源释放和恢复设备时允许重新查询。

对照数据保存于 `samples/3d/away3d-explorer/Validation/2026-10-19-performance.json`。软件 WebGL 帧间隔不代表用户设备的显卡性能；硬件效果需在当前浏览器重新录制确认。

## 复查命令

在仓库根目录编译真实状态对照入口：

```sh
haxe -cp test -cp ../hxmaker-openfl/src -lib lime -D html5 -main GLStateCacheChecks -js /tmp/hxmaker-state-cache-checks.js
node test/tools/run-state-cache-browser.cjs
node test/tools/profile-explorer-browser.cjs /tmp/hxmaker-performance.json
```

浏览器脚本支持 `PLAYWRIGHT_MODULE`、`CHROME_PATH`、`HXMAKER_TEST_BASE`。探索流程检查需在示例目录使用 `lime build html5 -D hxmaker_explorer_checks` 构建后运行 `test/tools/run-explorer-browser.cjs`；交付预览使用普通构建。
