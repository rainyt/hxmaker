# 静态与动态阴影缓存

后续已增加 `AUTO` 与主场景持久缓存，当前用法见[主场景几何缓存与 AUTO 策略](主场景几何缓存与AUTO策略.md)。以下记录显式静态／动态策略接入时的实现与基线。

`MeshObject.shadowMobility` 决定阴影几何如何缓存，默认 `ShadowMobility3D.DYNAMIC`。它不改变 `castShadow`、`receiveShadow` 或灯光阴影开关。

```haxe
import hx.render3d.ShadowMobility3D;

building.castShadow = true;
building.shadowMobility = ShadowMobility3D.STATIC;

for (mesh in character.meshes) {
    mesh.castShadow = true;
    mesh.shadowMobility = ShadowMobility3D.DYNAMIC;
}
```

`STATIC` 适用于地形、建筑和固定道具。同一级联的静态物体按材质状态合批，世界空间几何缓存在 GPU 缓冲中。相机、光方向、阴影采样参数变化时复用几何；静态物体移动、父级变换、几何修改、投射物增减时自动使对应缓存失效。它是更新策略提示，不会冻结物体。

`DYNAMIC` 适用于移动角色、活动道具和骨骼模型。几何保存于局部空间，根节点及其祖先的移动、旋转、缩放只更新绘制矩阵，不重新上传顶点。骨骼姿态或组内子节点变换改变时重新打包对应对象组，复用已有缓冲容量；所有阴影级联共用同一份上传。

同一个 `Model3D` 内的动态网格按最近的 `Model3D` 祖先分组，以减少每个材质图元单独绘制的开销；普通 `MeshObject` 各自成组。组内可见且符合投射条件的网格一起缓存，任一成员进入级联范围即可绘制该组，范围外部分由 GPU 裁剪。因此大场景宜标记为静态，多个独立活动角色宜分别创建模型实例。组内子节点发生变化仍需要重建该组。

可在运行中切换策略。MASK 材质的透明度、阈值只更新参数；图集 UV、顶点透明度和几何变化仍会重新上传。直接修改几何数组后调用 `geometry.invalidate()`。不透明及标准 MASK 材质继续支持投影；自定义片元代码与其他透明模式沿用原有限制。

`light.shadowAutoUpdate = false` 冻结的是整张阴影贴图，移动角色也不会自动更新阴影。需要时调用 `light.requestShadowUpdate()`。`shadowMobility` 则在正常阴影重绘中减少几何准备和上传，角色的阴影仍随动作变化。

## Blender 观测站

观测站导出器支持网格对象的自定义字符串属性 `hx_shadow_mobility`，取值为 `static` 或 `dynamic`，默认 `static`，非法值会在导出时报错。导出结果写入 `scene.json` 的 `shadowMobility` 名称映射，示例运行时将映射应用到导入网格。普通 GLB 不会自动获得此策略；其他项目在实例创建后配置 `mesh.shadowMobility`。

当前示例环境为静态，闸门为动态；十只霸王龙分别是动态模型实例。右侧面板显示最近重绘的静态、动态阴影上传 KB。按 `U` 关闭骨骼动画后仍然游走，可观察刚体移动零上传；再次开启可观察仅动态几何上传。静止画面复用时数据保留最近一次重绘值。

## 统计与代价

- `shadowStaticUploadedBytes`、`shadowDynamicUploadedBytes`：实际几何上传字节数，两者之和为 `shadowUploadedBytes`。
- `shadowStaticGeometryRebuilds`：按级联计数的静态几何重建。
- `shadowDynamicGeometryRebuilds`：按对象组计数的动态几何重建，跨级联不重复计数。
- `shadowGeometryRebuilds`、`shadowGeometryCacheHits`：保留按重绘级联计数的原有语义。
- `shadowGeometryBytes`：静态与动态 GPU 几何缓冲的预留容量总和，不含深度贴图。

十只霸王龙的当前采样：刚体移动时阴影几何从每帧 2646204 B 降为 0；骨骼动画时降至 923760 B，减少约 65.1%，静态环境为 0。该场景两个级联的阴影绘制从 4 次增至 24 次，以额外绘制换取较少的 CPU 打包和上传；不保证所有场景都更快。首次分配、容量增长、物体进入级联或策略切换会产生额外上传。

记录位于 `samples/3d/away3d-explorer/Validation/2026-10-19-shadow-mobility-dinosaurs.json`。这是 SwiftShader 软件 WebGL 对照，帧率和 CPU 提交时间不能代替实际显卡的录制。主场景的顶点打包、法线变换与 CPU 蒙皮仍保留原有路径，本次优化只处理阴影几何。

## 验证记录

WebGL2 默认 VAO 与 WebGL1 无 VAO 路径各通过 19 项阴影专项检查，覆盖静态复用、动态根与父级变换、负缩放、局部子变换、几何替换、MASK、策略切换、容量上限、两级阴影、关闭重开、上下文恢复与 GPU 句柄释放。缓存与强制重建的图像逐通道一致；多网格模型的局部空间路径另与静态世界空间路径比较，允许极少数栅格化精度差异（通道差值超过 3 的数量低于总通道数 0.1%）。

观测站 14 项探索回归与霸王龙 9 项功能／上传检查通过。Blender 5.2.2 LTS 后台从现有场景导出 83 个网格的策略清单，检查动态闸门、静态默认值和非法值拒绝，未覆盖可视化属性编辑面板。专项记录保存于 `test/shadow-cache/Validation/2026-10-19-shadow-mobility-webgl*.json`，探索与 Blender 记录保存于示例的 `Validation/2026-10-19-shadow-mobility-*.json`。
