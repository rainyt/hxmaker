# 二维场景切换索引修复说明

用户在恢复 hxmaker-openfl 的直接提交代码后，报告 samples 切换场景时短暂出现跨屏三角形和纹理长条。当前后端的普通图片实际通过 `DirectBatchDisplay` 和 `DirectBatchRenderer` 提交到 OpenGL。

## 静态检查发现

渲染器按批次序号复用 `DirectBatchDisplay`。同一对象可能先用于文字、图形等通用网格，再用于普通图片的固定四边形。

旧实现让两种用途共用 `indices` 数组。假设通用网格留下长度为 4096 的数组，切回普通图片后仅生成 64 个四边形、共 384 项索引，但上传时使用整个旧数组，并将 `gpuIndexCapacity` 设置为 4096。随后图片数量增加到 100 个四边形、需要 600 项索引时，容量判断不会触发重新生成，尾部便继续使用旧网格数据。错误索引可能连接不同图片乃至缓冲区中残留的顶点，产生长条或跨屏三角形。

这是代码中可以明确确认的缺陷，与截图现象相符；尚未通过运行示例证明它解释了截图中的全部异常。

## 修复

- 固定四边形使用独立的 `UInt16Array`，避免通用网格覆写。
- 固定缓存扩容时生成全部索引，缩小时继续复用完整有效的缓存。
- GPU 上传使用该独立数组，有效容量也取自该数组，并明确记录 16 位索引步长。
- 显式销毁批次时释放独立缓存；普通场景切换继续复用缓存。

保留了批次模式切换时令 GPU 索引容量失效的原有机制，没有通过每帧重新生成全部索引来规避问题。
